# WorkBuddy

WorkBuddy 将墨水屏设备与电脑端本地助理绑定，支持语音指令、读取回复和同步历史消息。服务端、电脑端和设备端需要同时满足以下配置。

## 配置与绑定

- 独立服务地址由 `main/cloudzao_endpoints.c` 的 `cloudzao_workbuddy_host` 配置，接口路径同样在该文件维护。
- 服务端需要启用 WorkBuddy 本地助理模式、百度实时 ASR 和 WebSocket 转发；电脑端需联网并保持对应账号的本地助理在线。
- 首次进入应用时使用手机扫码授权。设备凭证单独保存在 NVS，设备不持有腾讯 access token，不通过日志输出正文或凭证。
- 扫码授权成功后仍需查询电脑连接状态。设备不会代替用户批准电脑端操作。迁移服务时需同步配置手机授权入口和 OAuth 回调。
- 重新绑定由右上角菜单发起，确认框保留当前对话；新授权成功后才替换正式凭证并清空旧账号在页面内的消息。刷新二维码或离页不等于撤销手机上已经提交的授权。

## 页面操作

首页每页六个应用，WorkBuddy 位于第二页。圆点仅指示页码，实体翻页键首尾循环，切页先推白。普通返回保留应用页码，Home 返回第一页。像素视界显示名称 buddy，其他主题显示 workbuddy；应用图标等比缩放。

进入应用检查绑定时，聊天区居中显示应用图标；检查完成且没有消息时显示随机欢迎语，每次进入选定，后续刷新保持不变。标题连接状态区分未知、状态查询中、查询失败、在线和离线；进入页面查询一次，之后约每 30 秒查询。请求耗时会延长实际间隔，查询失败不会直接判为离线。

- 右上角无边框三点菜单提供“同步消息”和“重新绑定”。展开列表包含图标和分隔线，点击外部关闭。连接状态文字仅用于显示。
- 长按屏幕或 BOOT 键启动语音交互；顶部出现倾听波形后开始说话，松手结束。音频初始化在后台等待，不强制复位硬件；失败通过系统顶部弹窗提示。
- 屏幕左右轻点翻页；实体翻页键短按逐页、长按每秒十页，松手、离页或进入待机后停止。触及边界时停止连翻，长按上一页到达第一页不会退出应用。
- 盖板返回键先关闭菜单或确认框；对话存在上一页时翻到上一页，没有上一页时退出应用。实体 Home 始终返回首页。
- 网络未连接时隐藏刷新按钮；二维码可用时，其说明和刷新入口位于二维码下方。

## 消息与分页

自动回复通过回复查询接口读取正文，固定本次指令的受理编号持续查询。相同编号返回当前完整快照，覆盖已有气泡，不重复追加；等待状态表示本次暂未读到回复，不代表电脑任务完成。发送后定位到最新用户消息，回复更新保留当前阅读位置。

“同步消息”通过历史消息接口读取默认历史页，每次最多 20 条。设备按角色区分用户和助理，读取消息中的全部文本元素。相同真实消息编号的文本更新覆盖原内容。当前接口按新到旧返回，显示前反转为旧到新，同步完成后打开最后一页。重复同步替换当前历史快照；空结果保留现有对话。工具消息、附件和元数据不在文本气泡中显示。屏幕分页只处理已取回的内容，不自动请求下一批历史。

正文按纯文本显示，保留换行、空行与缩进，不解析 Markdown 或富文本样式，也不推断拼接正文中的角色。根据当前字体和气泡宽度换行，按内容区实际高度分页，仅创建当前页的文本控件。底部显示当前页码和总页数。

## 历史内存预算

正文、消息容器、行索引和分页索引只在 PSRAM 分配，按分配块实际大小统计容量和对齐空间，不回退内部 RAM。缓存不按固定条数或页数截断。

- 历史预算：PSRAM 总量的 1/32，最高 256 KiB。
- 空闲余量：每次历史分配后至少保留总量的 1/4，且不少于 2 MiB，供联网、音频和显示使用。此检查约束历史申请，不能限制其他模块后续分配。
- 单条正文最多 4 KiB，在 UTF-8 字符边界截断。
- 预算不足或分配失败时回收最早消息后重试；仍在缓存内的阅读位置保持不变。清空或销毁页面时释放历史分配。

网络 JSON 解析暂存和当前页 LVGL 控件不计入历史预算。HTTP 响应暂存上限为 32 KiB，超过时返回明确错误，不解析被截断的响应。以上数值是设备侧资源策略，不代表服务器历史总量。

## 音频、任务与待机

音频采集通过独立模块接入共享音频服务，复用同一输入任务和直通处理器提取 16 kHz 单声道 PCM。WorkBuddy 只持有自身音频占用，不改变百问 AI 的 AFE 和 Opus 发送路径。实时音频使用有界 PSRAM 环形缓冲；finish 包包含累计字节数和 CRC32，服务端最终确认后才提交电脑指令。网络失败或超时不会自动重发已受理的指令。

网络任务持有独立上下文，离页、换绑和待机通过取消门闩停止请求。录音启停交给音频工作任务，NVS 操作使用内部 RAM 栈；LVGL 生命周期不等待网络或硬件收尾。硬件未就绪、任务栈分配失败和并发名额不足均显示明确错误。

应用在前台声明软保网需求，不刷新用户无操作计时，不阻止自动待机，并尊重手动关闭 Wi-Fi 的设置。待机时停止录音、回复读取和状态查询，释放页面保网；用户唤醒后恢复连接，不自动录音或重复发送指令。已提交到电脑的任务可能继续执行，可用“同步消息”查看。具体电源策略见 [电源策略](../boards/common/power_policy/README.md)。
