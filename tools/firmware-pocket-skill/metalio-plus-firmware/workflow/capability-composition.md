# 从用户目标到能力组合

目标是完成用户的应用，不是完成所有模块的演示。先提取实际交互、数据去向、联网和后台任务，再选择必要组件；页面、算法、业务数据格式与任务拆分由Codex决定。

| 本次需要 | 可复用入口 | 业务作者仍需完成 |
|---|---|---|
| 任意新应用 | firmware-build生成器、设备HAL、实际字体/绘制与pocket-integration标准桥接 | 用户页面、状态和验收条件；探针页面不得作为成品 |
| 小状态/文本或大TF文件 | app-capabilities/storage与真实保存钩子 | 稳定文件路径、业务schema、首次缺档/损坏区分、写入失败保原稿 |
| 联网查询/网页工具 | wifi-standard、network设备配网示例、bounded_http_body | 扫描/密码页接线、真实服务响应和解析、缓存更新时间及失败状态 |
| 阅读/表单/中文输入 | font-support、text-input；只需密码时用英数输入 | 字段与编辑行为、实际可见区域和触摸命中 |
| 动画/声音/录音/长任务 | media/lifecycle/resources、TaskFence和资源预算 | 开始/取消/停止完成的语义、共享外设、持续任务对空闲休眠的影响 |

先完成最不确定的一条纵向路径。例如天气先让设备取得IP、取得并解析真实响应，再扩展页面；记事本先实际保存非空文本并重开，再扩展编辑交互。这是推荐顺序，可与已确认的UI或其他独立工作并行，不规定固定M阶段或BIN数量。

## 接入与复用边界

- 使用生成器时优先复用它提供的设备和标准协议代码；需要替换实现时用相同输入/输出与失败语义验证，不以复制过文件或编译成功作为行为证据。
- 协议数据与业务数据分开。标准适配器负责身份、run/receipt、公共配置与保存返回；业务回调只负责自己的恢复/持久化。宿主产品版本不是业务准入条件。
- 业务存储失败、协议不兼容和无线失败走各自诊断入口，不统一显示“插入原TF卡”。联网失败不阻塞启动确认；可选共享失败不阻塞已经完成的业务保存返回。
- HTML用于需求/UI确认：说明放真机框外。落地使用实际字库、原生像素与可触达区域检查；不承诺浏览器样式逐像素复刻。保留设计建议与用户要求的优先级。
- 能力目录没有某种题材不构成限制。已有组件覆盖底层时组合实现；遇到未覆盖硬件/SDK接口再查对应固定版本资料，验证一个窄路径，不默认载入完整官方整机。

## 输出与经验

本轮WORK记录组件选择、业务接口、关键依据和必要证据。只把本轮证实的可复用结论写为经验；未验证项标明边界，不修改已安装Skill。最终交付仍是同一BIN及中文使用/退出说明，不将工程操作细节或测试夹具显示给设备用户。
