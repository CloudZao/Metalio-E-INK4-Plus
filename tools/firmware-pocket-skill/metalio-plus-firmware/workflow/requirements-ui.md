# 从需求到设备界面

先整理应用目标、用户操作、数据来源/保存位置、网络/传感器/音频、主要异常态与验收条件。只问影响架构且不能合理推断的选择；给出默认方案继续推进。始终收敛到该用户固件的交付。

架构前读pocket-integration：同一应用BIN独立与口袋两态、公共数据与私有数据界限、存储模式和退出保存决定工程结构。联网应用同时规划独立配网及口袋公共配置读取，不能等写完天气页后才补。

预览形式由当前能力和需求选择：文字线框、SVG、HTML或生产渲染图都可。HTML是需求对齐工具，不是浏览器页面逐像素转换协议。真机框内只放用户将看到的UI，解释、风险和操作演示说明在框外；横竖屏都展示实际顶栏及必要错误态。按product-conventions强默认，有覆盖需求明确记录。

确认后由Codex或按需委派的UI适配Agent负责：真实像素尺寸和方向、Noto实际字形度量、字号/字重/对比度、换行截断、边距、触摸区域、灰阶/黑白、局刷策略、顶栏/帮助/返回一致性。复用device-interaction与font-support，不直接把CSS数值当硬件数值。

生产绘制和命中区域共源。至少检查最长中文标签、候选翻页、返回按钮隐藏后空位、错误/无网/无卡、锁屏/深休。适配中改变信息、操作或重要布局再请用户确认；合理字号与笔画修正可以自主完成并说明。主机预览通过只证明被检查路径，不等于真机波形和触摸实测。
