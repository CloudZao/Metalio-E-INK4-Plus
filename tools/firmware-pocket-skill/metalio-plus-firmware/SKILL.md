# Metalio Plus 固件创作 · V0.4

把用户想要的部件做出来。默认信任 Codex 的推理、工具和并行能力；提供已核对的接口、可组合代码与踩坑证据，避免重新探索设备底层。示例是起点，不限定题材、页面、业务模型或技术复杂度。

## 边界与开始

- 仅 Plus 4.7 / ESP32-S31；本版聚焦 Windows 原生 Codex。无需 WSL/Linux/Docker，不承诺其他宿主的已验证兼容性。
- 本目录是唯一 Skill 根。先读取 [握手](workflow/host-handshake.md)；进入实际开发后再建立独立 WORK，只把必要模块及代码复制到 WORK。安装包只读，不引入作者目录、其他历史项目、00 基线或旧版 Skill。外部资料不是已构建工程，也不是已验证结果。
- 开始开发时先读 [需求与 UI](workflow/requirements-ui.md)、[产品默认规范](skills/product-conventions/MODULE.md)、[双模式集成](skills/pocket-integration/MODULE.md)。确定存储、启动、保存和返回合同后再实现。协议最低要求与可覆盖的产品建议分开。
- 集成依据公开指南1.1与Plus设备绑定，不依据口袋产品版本白名单。本版提供标准适配实现；Plus.16是用户已确认符合该协议的参考宿主，不是唯一准入版本。协议细节按需查看包内快照，不要求读取宿主源码；旧local107不作为自动回退路线。
- 仅安装/加载Skill时，确认入口与随包资源可读即可完成，不下载工具、不要求Python或02、不启动探针。若用户同时给出需求，继续下面的开发流程。只安装选定版本，不叠加旧包。
- `02_测试预置_原始材料`是可选原件缓存。可记下用户提供的位置；实际构建时按[运维模块](skills/toolchain-ops/MODULE.md)先复验已有环境，再选当前缺少的阶段/资源。本地02和缓存优先，没有或部分缺失则从原站及可信镜像有限尝试；失败报告具体资源、地址和原因。安装成功、取料成功和环境就绪分别记录。

## 执行闭环

1. 明确用户目标与必要约束，补齐少数真正影响实现的选择。展示必要 UI；HTML 可选，解释文字在真机框外。确认后进行墨水屏适配，不把浏览器样式机械转为像素承诺。
2. 按下表选能力；只读入口摘要和相关接口。已有适配工程保留有效业务，新工程用 [构建模块](skills/firmware-build/MODULE.md) 的生成器接通底层、字库、顶栏和双模式。默认探针明确不是用户成品。
3. 完成实际业务：先验证不确定的网络响应、解析和存储，再组合进设备；使用生产绘制、命中区域和后台任务状态，不另造一套虚假模拟实现。
4. 按 [进度与证据](workflow/project-progress.md) 逐步交付可检查增量。普通构建错误自行定位；真正的权限、凭据、硬件或关键许可阻塞及时报告。长期无进度要诊断，不无限等待。
5. 按 [设备验证](workflow/device-validation.md) 和 [交付校验](skills/verify-delivery/MODULE.md) 检查实际 BIN、业务与双模式。默认可用 USB；无串口也继续生成并标注待真机验证。烧录目标和用户授权不由“插着 USB”代替。
6. 最终交付中文命名 BIN、中文使用/退出说明、验证范围、许可文档和必要源码/配置/证据路径。不要把“编译通过”说成“功能正确”。用户未请求继续扩展时收敛交付。

## 验证标准

正确性有层级：来源/静态审查 → 主机行为 → 目标编译/镜像结构 → USB日志 → 用户真机功能。逐项如实记录，历史样例通过不等于新组合通过。用实际实现做低成本检查；只在有新变化、失败或未解决疑点时扩大/重复测试。

可在当前 WORK 维护简短可复用经验，记录症状、适用版本、证据、修法与未验证边界；不要自动写回已安装 Skill。源码、配置、ELF、BIN 与导出副本关联到同一次构建，最终哈希必须一致。

最终回复许可提示保持一句话，详细内容随交付：本固件供学习参考，许可清单由 AI 辅助整理、可能遗漏；商用或分发前请主动复核，详见设备“帮助→开源许可”及《第三方许可与知识产权说明.md》。提示不替代实际许可义务。
