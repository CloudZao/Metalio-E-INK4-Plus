# 中英文输入法接入与验收

规则版本 Plus 0.2.0，文本行为继承记事本 1.0.6；候选排序已重新生成，使用公开许可的wordfreq 3.1.1数据，不沿用旧Jun Da排序。触摸短震按当前Plus的HAL新Down规则适配。第1—4节供实际接入；第5节是验收；第6节说明来源。可直接采用随包核心，也可按接口语义适配其他UI。

## 1. 词表与候选查询

资源位于本文件相对路径 `../assets/pinyin-candidates.tsv`。UTF-8，无 BOM，无表头；每行是“拼音键、一个制表符、按顺序连接的候选汉字”，LF 换行。键按 ASCII 升序排列且不重复；一行内的汉字不重复。不同读音下出现同一个多音字是正常情况。

读取资源并生成工程只读常量或索引，默认编译进应用，不给输入法额外增加 TF 或网络依赖。允许改变存储形式，但不能改变键、字符或候选次序。资源被移除或散列不匹配时明确报告，不能由模型临时补一份词表。

查询约定：

- `Candidates(s)`：只接受 1—6 个 ASCII 字母，统一小写；`v` 用于 `lv`、`nv`、`lve` 中的 ü。只有完整匹配的键返回候选，返回顺序与该行一致。
- `IsPrefix(s)`：同样先验证和归一化；非空字符串是某个词表键的前缀时返回真，包括完整键本身。只用于“可继续输入”的提示，不把前缀展开为预测候选。
- 空串、超长串、空格、声调数字、标点和 `ü` 原字符均不自动修正为拼音。合法字母组成但未匹配的输入仍可保留在拼音栏，供退格、清空或转为英文字母；不要拆分整句，如 `nihao` 没有自动分词候选。
- 按 Unicode 字符拆分候选，不能把单个 UTF-8 字节当汉字。本版词表每字恰为三个 UTF-8 字节；这个事实不能用于任意正文、表情或未来扩展字集的切分。
- 不在运行时改为GB2312顺序、全表Unicode顺序或按点击学习重排。生成时只有相同权重或缺失权重的候选使用Unicode码点作稳定次序；只读查询可重复。

## 2. 宿主接入边界

需要的输入条件仅是：目标输入框、有效 UTF-8 初始文本及光标、字节上限、单行／多行、初始中英文模式。宿主提供文本提交、单行确认、绘制／刷新及已统一的触摸反馈能力；可以用普通函数或现有控件事件，不要求建立新的框架或固定字段协议。

保持三类状态分开：

1. 已提交文本和位于完整字符边界的光标；
2. 待选拼音、完整候选序列、当前候选页；
3. 输入模式、符号页、大小写、焦点及已经完成显示的画面版本。

一次提交必须是整体成功或整体失败：先检查字段允许的字符、完整插入片段的字节数、光标边界与可用容量，成功后才清空待选拼音和候选页。失败保留正文、拼音、候选和光标，并给出可理解的提示。字节上限指文本内容；C 风格缓冲区还须额外容纳结尾零字节。

宿主决定具体上限、文件名合法性、URL 规则、取消编辑与保存方式。单行输入不能插入换行；不强制所有应用使用 `.txt`、3072 字节、`/notepad/` 或相同屏幕方向。输入法输出已提交文本，不直接操作 NVS、TF 文件、公共网络配置或口袋交接。

字体需要覆盖全部启用的候选、键盘标签和实际允许输入的字符。生成或裁剪字体由宿主处理，不能因缺字就偷偷删除词表候选；应报告缺字并补齐所需字形。输入法文件中不携带完整字库或字体引擎。

## 3. 按键与提交规则

默认中文逐字拼音；候选每页 5 字。候选数量和字形大小先沿用该基线；确需更改每页数量时，显示、触摸编号、翻页和数字选字须一起适配。默认键盘保留 QWERTY 字母、数字和符号入口。底部依次是“符号、退格、空格、换行、大写／小写”；拼音栏右侧从左到右是“清空、英数”，英文模式右端显示“拼音”。尺寸、坐标和横竖屏布局由宿主调整，文字与触摸区域必须一致。

| 事件 | 待选拼音非空 | 待选拼音为空 |
| --- | --- | --- |
| 中文字母键 | 追加归一化的小写字母，最多 6 个；重新查询，候选页回到首页。超长不插入、不截断已有拼音。 | 开始拼音组合；符号模式下则按直接字符处理。 |
| 英文模式字符键 | 正常切到英文前须先处理拼音，不让它隐藏遗留。 | 按当前大小写直接插入允许的英文、数字或符号。 |
| 点击候选 | 插入当前显示的该字；成功才清拼音、候选并复位页码。 | 空候选不插入。 |
| 数字 1—5 | 选择当前候选页对应位置；该位置为空时不插入数字，也不丢拼音。 | 直接插入数字。 |
| 其他数字或标点 | 提示先选字、按换行转字母或清空；保留当前状态。 | 直接插入宿主允许的字符。 |
| 空格 | 提交当前候选页的第一个字；无候选时保留拼音并提示，不插入空格。 | 插入一个 ASCII 空格。 |
| 退格 | 删除最后一个拼音字母，重新查询并复位候选页；不删除正文。 | 删除光标前一个完整 Unicode 字符；开头无动作。 |
| 拼音栏的清空 | 清除拼音、候选和候选页；已提交文本与光标不变。 | 对文本无影响，英文模式同样如此。 |
| 换行／单行确认键 | 将当前拼音作为一段小写英文字母插入；成功后清空拼音和候选；这一次不换行、不执行单行确认。 | 多行插入 `\n`；单行执行宿主明确的确认动作。 |
| 英数／拼音、符号／字母 | 先提示处理未完成拼音，保留输入，不静默丢弃或自动选字。 | 切换相应模式。中英文切换时回到字母页和小写状态。 |
| 大写／小写 | 中文拼音仍归一化为小写。 | 英文字母按所选大小写插入。 |
| 候选上一页／下一页 | 只改变候选页，边界不越界、不循环到意外位置。 | 无动作。 |

“清空拼音”与应用的“清空正文”是不同动作，不共用一个会删除正文的处理器。单行输入可在有拼音时把确认键显示为“字母”，无拼音时显示“确认”；标签变化后，触摸语义也要经过第 4 节的显示版本检查。

切换到另一个输入框、关闭编辑、保存或退出前，宿主须明确处理未提交的拼音：让用户选字、按上述规则转为字母、清空，或明确取消这次编辑；不能把上个输入框的拼音带进下一个输入框。对同一框移动光标时，候选可保留，但实际插入必须使用当前合法光标，不能使用旧画面的坐标推算新位置。

## 4. 墨水屏、触摸与振动

显示状态包括“逻辑上已变化”和“屏幕已成功刷新完成”，二者不能混为一谈。

- **异步处理。** 输入更新与屏幕刷新分开，快速按字母时可以累计输入并合并待刷画面；不因屏幕 BUSY 就丢掉全部触摸。使用有界队列或等价方案，防止长队列积累成跨页面误操作。新接入时要处理队满或入队失败，提示忙或采取有界的回压，不把失败当作已接受；不承诺无限连击也不会丢键。
- **以已显示的触摸区域判定动作。** 已完成的画面及其触摸映射一起生效。静态字母、退格等键在焦点、模式、布局仍一致时可以继续处理；屏幕换页、弹窗或键盘模式切换后，旧映射不能继续生效。
- **候选必须匹配。** 点击候选、空格选字、数字 1—5 选字，以及候选翻页，均须确认已显示的拼音与候选页等于当前状态。否则保留输入并等刷新，不选择用户尚未看见的新候选。
- **动态键同样检查。** 单行键的“字母／确认”含义随拼音变化：提交拼音后，在新画面完成前再次点击，不能偷偷执行确认。点击正文定位光标时，也必须保证显示的文本与文本页仍对应当前内容。
- **切页清理。** 焦点或语义变化时隔离旧触摸事件，等待旧触摸释放后再接受新页面的点击。弹窗只响应弹窗自己的控件，不能穿透到底下的键盘。
- **帧缓冲稳定。** 传输未结束时不能覆写驱动正在读取的帧；只有刷新成功完成才推进已显示版本。刷新失败时保留内存中的文本和拼音，处理失败请求后再重试；不能永远等待一个不会成功的旧版本号。
- **刷新策略。** 默认黑白快速刷新输入界面；进出页面及需要清理残影时使用已验证的清屏策略。局刷次数和清屏时机由面板与宿主决定，不规定每按一键就全刷，也不承诺电脑键盘般的显示速度。
- **短振动。** 当前 Plus 在通过安全门的合法新 Down 统一触发一次非阻塞短震，包含空白和不可用控件；HAL已经处理时，IME不得再次Pulse。持续按住或滑动不重复，锁屏、Flash、过期场景拒绝的事件不补发。具体队列和时长由板级适配确定，不把旧输入法约22ms当机械实测保证。震动只表示新触摸反馈，被候选显示版本保护拒绝的操作仍不能当成成功选字。

这些是接入时要求的可观察行为，不要求复制原工程的线程名、队列长度、GPIO 或特定驱动。调用宿主已确认的显示和振动接口。单行／多行是本规范提炼的宿主适配条件，原记事本通过页面类型区分，不能宣称已有一个同名的通用 SDK 接口。新应用仍需完成上述适配与验证。

## 5. 关键验收

先检查第 6 节资源指纹、402 个唯一键、每行无重复候选、4415 次候选出现及 4262 个不同汉字。对生成进工程的表进行全量逐行比较，确保键、字集和顺序与 TSV 一致；抽查几个拼音不能代替完整数据比对。

| 场景 | 预期结果 |
| --- | --- |
| 查询 `si`、`SI`，重复查询 | 两者相同，前五字为“死、四、斯、司、丝”；无“以、已、厕、食”，次序不随点击改变。这是当前数据结果，不是手机输入习惯的质量保证。 |
| 查询 `shi`、`ai`、`an`、`chi` | 首字分别为“是、爱、按、吃”；用当前生成报告核对全表，不能沿用旧版本断言。 |
| 查询 `lv`、`nv`、`lve` | 分别包含“吕／绿”、“女”、“略／掠”。`ü` 原字符不作为输入拼音键。 |
| 查询常用多音 | “重”在 `chong/zhong`，“行”在 `hang/xing`，“长”在 `chang/zhang`，“乐”在 `le/yue` 均可达。 |
| 查询 `sh`、`shi`、空串、`shi4`、`nihao` | `sh` 无候选但为有效前缀；`shi` 既有候选也是前缀；后三者无候选且非有效前缀。输入栏仍允许保留 `nihao` 并转字母。 |
| 输入 `SI` 再按换行 | 插入小写 `si`，无额外换行，拼音和候选清空；再按一次，多行才换行。 |
| 输入 `si` 后点拼音清空 | 正文、光标不变；候选和拼音为空。英文模式点击清空也不删正文。 |
| 待选拼音非空时退格／切换模式 | 退格只删拼音；切换模式先提示处理，不能丢拼音。 |
| 候选翻页后按空格或数字 | 选择当前已显示页对应的字，不是整张词表首页的字；空位置不插入。 |
| 正文 `中A` 末尾连续退格 | 依次得到 `中`、空串，UTF-8 一直有效；中间插入也不劈开字符。 |
| 文本上限 4 字节，正文为 `中`，待选拼音为 `si`，按换行 | 插入失败，保留 `中` 和待选 `si`；不能只插入 `s` 或先清掉拼音。上限由测试宿主设定，不是产品固定值。 |
| 连续快速按字母，同时刷新；随后选字 | 被接受的字母顺序不乱、不因 BUSY 静默消失；未显示的新候选不能被旧触摸选中。 |
| 单行有拼音时快速连续点动态确认键 | 第一次只提交字母；新画面未显示前，第二次不能变成确认并关闭输入框。 |
| 切换输入框、弹窗、刷新失败 | 旧事件不穿透、不跨焦点提交；输入失败或刷新失败保留草稿，后续能继续处理。 |

用宿主已有测试能力验证能在电脑上验证的部分，并检查界面文字、触摸区和字形覆盖。输入速度、振动手感、残影和物理刷新效果仍需实际设备；没有实测就列为待验收。不要因为本基线在记事本中可用，就声称另一个应用、执行端或新布局已经通过真机验收。
