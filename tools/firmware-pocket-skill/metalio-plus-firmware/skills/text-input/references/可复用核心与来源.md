# 最小查询与编辑核心

需要中文输入时读取。`assets/ime_core.h`是可直接编译的C++14头文件，包含查询、UTF-8光标/退格、原子字节上限、单行/多行及候选显示版本检查；不包含绘制器、键盘坐标、字库、持久化或触摸线程。

1. 用`table_tool.py --header <工程生成目录>/pinyin_table.h`生成固定表，将`ime_core.h`加入工程并把生成目录加入include路径。
2. 业务创建`Editor(byte_limit, multiline, page_size)`，`Reset(text,cursor)`导入有效文本；字节限制是本业务选择，不默认套某个记事本上限。同一业务/UI线程持有并修改Editor，显示线程只消费复制的快照；这个小核心不是线程安全容器。
3. 静态字母与退格及时调用`TypeLetter`、`Backspace`。中文组合态的直接符号插入、切模式会返回`CompositionPending`，由UI提示用户先选字/转字母/清空；不静默删除草稿。
4. 一次绘制使用一致的`Text/Composition/VisibleCandidates/Revision`快照。只有对应物理画面成功完成，才把该`Revision`记录为`displayed_revision`。真实页面/焦点变更仍由外层输入路由隔离旧触点并等待松手，不能只靠本类代替场景门。
5. 候选、候选翻页、空格/数字选字、动态Enter、点击定位光标传入已显示revision。返回`StaleView`时保持草稿、请求更新画面，不把旧选择自动套到新候选；不能记作成功输入。拉丁模式已确定为直接字符的按键可调用`InsertLiteral`，避免把独立UI语义全部强制串行等待刷新。
6. `Changed`后请求合帧绘制；不在此核心内阻塞等待面板。`ByteLimit/Invalid`保持原文；`Confirm`交给单行业务。`ClearComposition`仅清拼音。进入保存/返回/其他输入框前由业务显式处理尚未提交的组合串，再保存`Text()`。

`examples/input_flow.cc`是主机接线例子，不是假装已经接上真机。`tests/ime_core_test.cc`也测试同一个生产头文件。核心没有TF/Wi-Fi/口袋依赖，单行SSID可只用英数输入或采用等价轻量控件，无需强行编入中文候选。

## 数据许可与代码边界

候选头文件中的派生数据有自己的许可，见`../licenses/ATTRIBUTION.md`；不要因生成器由本项目编写就把数据改标为自有。正常应用开发直接使用冻结数据，作者维护时才读取`../generation/生成方法.md`。

当前核心没有整句预测、用户学习或智能纠错；这是功能边界，不以“输入法”名称暗示具备这些能力。有需求可以扩展，但先明确数据来源与真实测试，不从商业输入法目录抽取词库。
