# 维护者的可复现生成方法

普通应用开发只使用随包TSV、`table_tool.py`与需要的输入核心；不用下载本节输入包。这里用于明确版本升级或审查数据来源，不是每次生成BIN的步骤。

1. 从 `sources.json` 的官方PyPI固定URL取得wordfreq 3.1.1与pypinyin 0.55.0两个轮子；下载物保存在任务工作目录，不放入Skill或原始材料02。先核对其SHA。
2. 使用独立Windows Python环境，准备读取器`msgpack==1.1.2`。它仅用于编写期解析数据，不进入Skill或设备。无需安装整个wordfreq及其分词/语言依赖。
3. 在新的输出目录运行：

```powershell
python "$TextModule\generation\generate_source_tables.py" --wordfreq-wheel "$Cache\wordfreq-3.1.1-py3-none-any.whl" --pypinyin-wheel "$Cache\pypinyin-0.55.0-py2.py3-none-any.whl" --output-dir "$Work\rebuilt-pinyin"
```

生成器核对轮子指纹，临时解开pypinyin再生成默认映射，并按`common-readings.json`保留显式修正；不会执行历史工程脚本。`compat-characters.txt`只是已排序的4262字兼容需求，不携带旧候选排名。它来自旧输入集合，源头曾由字体可显示范围选择；该历史局限保存在sources，不冒充独立新语料。排序仅来自固定wordfreq数据；11个精确单字条目没有权重时保留末尾、码点排序，不下载其他词频、不补旧排名。

输出的TSV、权重表和报告应与随包对应文件逐字节相同。明确变更输入时另建数据版本，更新指纹、预期用例和来源许可，再发布；不能直接覆盖安装目录来通过旧哈希校验。

## 验证方法

- `tests/test_table.py`检查402键/4415候选出现/4262字、全表排序、全部输入字符可达、生成头文件逐行等价，以及未知改动拒绝。
- `tests/ime_core_test.cc`编译实际`ime_core.h`，检查UTF-8边界、原子插入、页选择与已显示版本、单行动态确认等。
- 显式固定数据样例是来源回归，不代表习惯排序质量。尤其多音字在所有读音共享词条权重；“省”在`xing`靠前、“死”在`si`靠前是当前源产生的结果，不能说已按每个读音优化。实际输入手感、显示、触摸仍需新应用真机验证。

旧Jun Da原文件和历史版本不在本模块内重新分发；历史版本不因新表而修改。
