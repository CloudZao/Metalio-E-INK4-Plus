# 多能力资源预算与共享硬件

在显示+Wi-Fi/TLS+音频/编码叠加时读取。四类资源分开记：最终镜像、PSRAM大块、内部任务栈/工作块、内部DMA及最大连续块；不能用Flash/PSRAM剩余量证明DMA足够。

`resource_budget.h` 提供有溢出检查的 DmaBytes、当前目标SDK的 ReadMemorySnapshot 与保守 HasDmaBudget。先记录分配前后数值、真实任务栈高水位和峰值；预算通过不承诺分配必成功，仍检查每次创建/分配结果。

仅录音的已核对实例：I2S从机RX、6描述符×256帧×2槽×4字节=12288字节；不是全双工或所有项目最佳值。15秒PCM16/16k mono为480000字节，可以放PSRAM；DMA和SDK要求的内部栈不能随之搬到PSRAM。不盲目缩小未测过峰值的TLS/编码栈。

[shared_audio_reset.cc](../examples/shared_audio_reset.cc) 实际调用基础HAL的ResetAudioPower协调P14。其返回仅证明共享轨复位调用成功，不冒充UART握手/I2S创建/采样成功。普通音频停止关闭PA并释放通道，不拉低P14；真正深休由统一HAL在物理画面完成后关轨。不要在Flash lease内重入复位门，也不持I2C全局锁长睡。

100Hz系统下1/2/5ms转换可能为0tick；确需阻塞时用事件/通知或至少1tick。不能靠提高线程优先级和忙轮询解决等待问题。

组合验证挑真实交叉点：录音时显示、Wi-Fi/TLS峰值时初始化音频、取消时准备未结束、返回时部分写入未完成。先主机验证控制和所有权，再用少量真机测量验证资源、采样和出声；不能把旧录音机单独通过等同于新组合通过。
