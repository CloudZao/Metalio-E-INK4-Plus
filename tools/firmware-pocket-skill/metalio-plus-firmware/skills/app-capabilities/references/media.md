# 声音、线稿和动画的窄复用件

仅在相应需求中读本页；普通天气/记事本不自动引入录音、Opus、STT或整套云聊天。

`assets/plus_services/media_helpers.h` 与 [media_pipeline.h](../examples/media_pipeline.h) 包含：

| helper | 实际范围及边界 |
|---|---|
| MicSlotToPcm16 / ExtractMicrophone | Plus蓝牙芯片左/偶数麦克风槽；32bit右移12等效整数运算及历史±32767限幅；不混右侧回采参考 |
| Pcm16ToPlaybackSlot / MakePlayback | 平方音量曲线、64位乘法、左右复制单声道；不代表两路独立麦克风或提高采样率 |
| WriteAllPcm | 有取消检查的部分写入推进；成功仅表示全部入队，之后仍等真实DMA排空再停PA |
| CompositeLineArt / CompositeGray4 | 白底alpha合成后落黑芯；前者8位预览域，后者0..15生产灰域，不把两种编码混用 |
| ChangedPixelsAreBinary | 只检查变化像素新旧均为黑白；默认白=255，也可明确白=15用于灰4；仍要求底层跳过未变像素 |
| FrameReceipt | 只允许一帧在途，等待物理完成且健康才推进；目标间隔不是实际帧率 |

这些是可执行算法/时序例，不是完整录音驱动或自动将HTML编译成固件的工具。音频硬件初始化、UART应答、WAV持久化和实际图层/驱动接线仍按 [设备声音规范](../../device-interaction/references/audio-animation.md) 完成。

短按键音、游戏提示音还须核对TX实际传输进展、PA预热和会话就绪，不能仅以PCM生成或WriteAllPcm入队判成功；频繁短音优先复用就绪会话，具体见[设备声音规范的“短音效：功放预热、TX 就绪与会话复用”](../../device-interaction/references/audio-animation.md)，无声时先用较长测试音排查，最终以真机试听确认。

用最终画布、固定缩放和锚点；保持原alpha和轮廓掩码，透明外部像素先排除，不能用黑芯填满透明背景。动态固定网点不随机每帧重采样；恢复真灰背景时改走灰阶刷新，不用DU硬套。动画等待物理回执，音乐业务时钟独立。

已有完整HTML游戏/音轨移植时，读取其真实脚本、音轨和业务数据，列源PCM、预混、前景增益、BGM、总音量的完整链；不从截图猜逻辑，不把预混和声再混一次、不将所有声部RMS拉平。新应用的HTML需求确认仍只确认需求/UI意图，需要专门墨水屏适配，这不是同一场景。

先建立少数明确参数的小标定应用，调用同一生产helper和素材；用户认可的参数固化到真实调用点。回到完整应用验证声画、弹窗、静音、锁屏、保存退出的组合，不能只修改README。主机PCM安全不替代用户试听，像素正确不替代真实残影/灰阶观感。

基础录音已有历史用户接受；音质根因和完整时长边界未因此全验。STT目前没有完整成功案例，本包不提供伪造后端。新helper及重新组合的固件仍需目标构建与真机验收。
