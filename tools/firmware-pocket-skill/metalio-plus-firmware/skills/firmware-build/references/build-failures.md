# 构建排查：按症状展开

| 症状 | 已知条件与处理 | 不应替代成 |
|---|---|---|
| S31 target 不支持/工具找不到 | 固定 IDF 6.1.0、`--preview`，使用运维 Activate.ps1；核对真实 `IDF_PATH`、Python、RISC-V 工具版本 | 回退 S3、随机升级整个 SDK |
| SDK 从 ZIP 组装后版本判断失败 | 运维按已核验 SDK 版本建立安装产物 `version.txt`，记录提交与来源 | 给任意源码伪造版本 |
| Windows 路径过长、编码/转义错误 | 新运行目录用短 ASCII；Python UTF-8；PowerShell 路径使用变量/引号 | 全局更换用户目录、默认要求 WSL |
| UART UHCI / IOT 组件缺失 | 固定官方 commit 的缺声明，准备脚本增加组件 manifest 与锁；已有工程按真实引用声明 | 删除所依赖源码或写空函数 |
| `lang_config.h` 不存在 | 固定词条源码经 SHA 验证机械生成 742 项声明 | 从其他语言/旧项目复制不一致头文件 |
| `mmap_generate_resources.h` 未生成 | 固定官方项目资源目标先于 main，脚本补 CMake DEFER 依赖 | 重试碰运气、提交空资源 |
| qoi-conv 缺失，虽未启用 QOI | 官方资源脚本仍 import；原始依赖集包含 qoi-conv/NumPy | 删除资源处理、装随机版本 |
| 组件解析仍访问网络 | 运维材料通道只管固定依赖；确认当前项目锁与组件存储是否匹配，新增业务依赖记录来源/版本 | 强制全局离线或默默换依赖 |
| ccache相关最小编译挂起 | 用同一源文件/编译命令比较启用与绕开缓存；证实后仅该构建进程禁用 | 全用户永久禁缓存、反复杀全部ninja |
| 日志空或进度停滞 | 结合所属PID树、日志时间/大小、依赖下载和最小编译排查；管道阻塞只是候选 | 没有新输出就认定CPU不足或stdout写满 |
| 运行时刷新欠载/启动确认卡住 | Flash 写入/大摘要与 EPD 物理扫描共用互斥门，排空画面后操作；网络不作为启动确认前提 | 禁用镜像验证或改电压 |

这些是具体版本/历史构建与应用经验；先核对当前错误是否同根因。修复后重新构建、校验实际产物；上述经验不是本次生成应用已通过的证明。
