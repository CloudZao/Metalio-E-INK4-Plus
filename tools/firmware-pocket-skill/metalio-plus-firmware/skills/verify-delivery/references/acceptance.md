# 按产物和证据验收

本版目标是同一份 BIN 在独立模式及遵循指南1.1/Plus绑定的宿主中可用。Plus.16是用户已确认符合该协议的参考宿主；不重复要求审查其源码，也不以其产品版本作为应用准入条件。验证分层记录，不把编译、镜像、主机行为、用户观察互相替代。用户确认的 UI 是实现目标，预览通过并非设备通过。

## 写业务前检查接入

用本次工程中的真实位置和证据核对下表，不只列函数名。能在主机发现的接线错误先处理，避免把明显遗漏留给用户烧录。

| 项目 | 需要的证据 |
|---|---|
| 配置继承 | 通用/芯片 defaults 的保留与覆盖依据；最终 sdkconfig 的 S31、Flash、PSRAM、主任务与工作任务栈、WDT 配置。不能只抄芯片文件或用放宽 WDT 掩盖阻塞 |
| 外设初始化 | 实际调用链覆盖显示、触摸、实体键和震动；初始化结果处理，队列/回调的生产者与消费者。不能因文件被编译或注释声称“自动初始化”就算接通 |
| 启动资源 | 在实际执行该路径的任务上核对栈/缓冲预算，不能拿后来创建的 GUI 任务栈替代 main 任务；目标编译/可得栈分析与设备余量分开 |
| UI 落地 | 同源布局参数、绘制/触摸变换、字体覆盖、图像编码/尺寸及裁剪；用生产绘制路径的可得像素或几何输出检查，明确其与物理屏幕的差别 |
| 双模式 | 真实分区分类、恢复/身份、运行 app 摘要、平台启动确认、started/saved 顺序和返回；使用结构定义/接口，不手写未经验证的元数据偏移 |
| 保存与失败 | 需求需要的原文件、临时文件、恢复和错误路径；失败不删唯一完好数据，不把所有打开失败都当“第一次使用” |

这里的检查没有运行证据时记录为源码审查。业务主机测试选与需求相关的布局/事件、UTF-8、存档格式、恢复、取消等实际场景，运行并保存结果；不能把“读代码觉得正确”命名为主机功能测试通过。

## 对同一 BIN 做真机验收

先用包内标准协议测试核对真实适配器：以指南独立构造JSON/记录样例，覆盖重复键/额外字段、历史身份、单槽有效、错误回执和closed不等于saved。真实两态业务仍需下表结果；宿主历史验收不是新应用的验收。

按 [设备验证流程](../../../workflow/device-validation.md) 操作。每轮绑定完整 BIN SHA-256、app 身份/载荷、设备标识、当前模式、管理器版本和反馈时间。

| 模式 | 必须观察的结果 |
|---|---|
| 独立 | 已授权的完整镜像从 0x0 烧录后启动本应用；核心业务、UI和触摸可用；无口袋环境不造 identity/run/receipt |
| 口袋 | 由符合指南1.1及Plus设备绑定的宿主正常导入同一完整 BIN；实际启动此 app；平台启动确认与 started 成功；运行核心业务 |
| 两种模式各自 | 显示与命中一致、研墨、锁屏/恢复、5秒深休/5秒唤醒；按需求验证存档、网络和声音。USB日志不能代替真实触摸/屏幕反馈 |
| 口袋保存返回 | 业务变更→保存→saved→回管理器→再进入，状态符合约定；返回失败应留在应用并恢复真实可操作状态，不报假成功 |
| 数据恢复 | 按用户选择的存储模式验证保存和重启/重入；无持久化业务时明确“无须恢复”的设计并验证不误写控制记录，不凭空增加存储 |

不因暂时缺设备或用户反馈而编造通过。可先交付标注 pending 的 BIN，并明确缺什么；待结果回来继续当前工程，不要求重新访谈或重写整个应用。

## 证据记录的用法

`validation_record.py init` 从实际 BIN 建立空验收记录。将用户已确认需求补充为具体用例，必要时增加 checks 条目。每个 pass 要填 observed（实际结果），evidence 包含 kind、path、sha256；路径相对记录文件目录或本轮绝对路径。kind 为 host-test、source-review、serial、user-observation 或 hardware-test。真实设备检查填写 device_identity，可用端口/USB序列号和用户设备名称组合；无硬件序列号时不要虚构。

联网应用在init增加`--wifi`，带入生产联网主机检查和两态配网项目。记录`integration_host.name/version`为本轮实际宿主；这是证据身份，不是版本白名单。不得预填Plus.16为已经实测。若暂无线缆/设备仍可交付BIN，相关项保持pending。

示例仅说明数据结构，不是通过证据：

```json
{
  "mode": "pocket",
  "requirement": "保存后返回口袋，再进入仍有刚才内容",
  "status": "pending",
  "observed": "",
  "evidence": []
}
```

保存实际日志/用户反馈文件后，使用 `Get-FileHash -Algorithm SHA256 -LiteralPath ...` 或 Python 取得该证据文件摘要。填入的 pass 应来自对应测试；检查器只验证记录一致性，不裁决文字是否属实。重新构建导致 BIN 改变时重新 init，旧记录保留历史，不改旧 hash 给新 BIN 继承通过。相同字节的复制无需重新烧录，但必须重验接收副本。

## 最终交付

- 一份中文命名BIN，正确的设备、应用版本、大小、SHA-256和独立起点0x0；口袋模式走管理器导入，不能手动把整机写入 app 槽。
- 简明使用说明：本应用功能/退出、TF/联网要求、协议与设备绑定、独立/集成各自实际通过与待验收项。实际测试的宿主版本可列证据，不写成唯一允许版本。
- 交付清单：Skill版本、固定材料/SDK提交、实际 BIN 身份、构建/结构/业务/两种真机证据和最终副本校验。源码、ELF、配置、关键日志和修复记录留在 WORK 供复现，不混进原始材料或 Skill。

普通调试授权不涵盖整片擦除、格式化TF、删除用户存档或公开发布。测试独立布局可能覆盖既有管理器/数据，事先明确这一步的范围与恢复安排；已有具体授权沿用，必要的新取舍才询问。
