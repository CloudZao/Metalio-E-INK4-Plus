# 把确认的 UI 实现到 Plus

需求访谈/UI 确认沿用主流程。这里解决预览到实际渲染、刷新、命中的接入，不要求 HTML 与墨水屏逐像素相同，也不指定所有应用必须使用 LVGL。

## 共享布局，不重新猜坐标

默认示例为684×1216逻辑竖屏，`app_view.h::MakeLayout`同时供生产绘制和命中，支持横屏参数。其他页面可沿用一份`layout.json`生成几何参数：

```powershell
& $Python "$SkillRoot/skills/device-interaction/scripts/layout_tool.py" "$Work/app/layout.json" --header "$Work/app/main/app_layout.h" --wireframe "$Work/layout.pgm" --report "$Work/layout-check.json"
```

检查坐标/尺寸为整数、非空、边界内、ID 不重复、交互矩形不意外重叠。明确允许的重叠层用相同 `overlap_group`，业务必须定义命中优先级。此检查不覆盖所有视觉元素或字体；PGM 只是线框，不是正式字体输出。

生成的 `Rect` 同时传给 `plus_ui::Box/Fill` 和 `plus_ui::Contains`；点击范围为 `[x,x+w) × [y,y+h)`。其他布局引擎可以替代生成器，但布局和命中必须来自同一来源，不能各维护一份数值。

## HTML需求预览到原生生产页面

HTML用于确认页面、内容、操作和状态。真机框内是拟交付UI；原型说明、方案解释和确认控件放框外。确认后由一个明确负责的实施Agent完成墨水屏适配：真实字体、可读尺寸、顶栏、触摸范围、业务状态与刷新接线。不是截图缩放，不是逐像素照搬CSS，也不宣称存在通用HTML自动转换器。

先跑通关键页面的生产渲染和命中，再扩展相同组件；小的原生字体适配直接落实，影响内容或操作方式只确认受影响处。`main/app_view.h`是能力演示，不把计数页当成用户需求。

Windows已有MSVC时运行本模块`scripts/verify_native_ui.ps1 -Output <Skill外的检查目录>`：从包内字体准备出发，编译实际生产renderer，检查横竖屏/两模式/可选Wi-Fi、完整许可分页、旋转编码与帧/idle状态，输出gray4/PBM/PGM。它不操作USB、不安装WSL、不证明面板已显示。没有主机编译器可继续原生目标构建，记录该项未执行。

## 实际像素与输入检查

- 原生 framebuffer 是物理 1216×684，4bpp 偶数 X 在低半字节。逻辑映射 `px=y, py=683-x` 只做一次；HAL 的触摸输出已经是逻辑坐标。
- 正式中文页面使用对应字体的真实 advance、行高、baseline 和字形位图；不把浏览器 CSS 字号当成设备字高。核对文本覆盖、换行、裁剪和灰度，尤其顶栏返回按钮与状态提示。
- 能在主机运行生产绘制器时，保存它输出的实际 framebuffer；也可在用户允许的设备调试中导出同一缓冲。用 `preview_native_frame.py frame.gray4 preview.pgm` 解码查看。工具检查原生长度 415872 字节并执行同一旋转；它不能证明物理面板、触摸或最终波形已验收。
- 重点检查四角、按钮边界内外、长标题、中文/数字混排、状态提示、锁屏与返回后页面；独立隐藏返回口袋后空间回收，帮助完整许可可达。按需求做，不固定所有项目控件与数量。
- 先输入事件→应用状态→完整软件帧→物理显示完成。绘制成功但刷新失败，不更新“已显示状态”，不允许按一个还未显示的新候选/布局操作。

## 不靠用户重新设计来掩盖实现偏差

先尝试用设备原生字体、真实布局参数和正确刷新实现已确认体验。若硬件约束导致实质布局变化，展示具体差异并请用户确认；小的实现细节无需重新访谈。不能到交付时才在笔记里记录“按钮其实放不下”。

真机需要看到屏幕并实际点按。串口显示事件计数只是链路证据，不代替用户对位置、触感、残影和锁屏恢复的确认。
