# 可选声音、语音服务和动画

仅在需求涉及相应能力时读本文件。普通记事本、天气、阅读器不要因此引入录音、Opus、ASR、账号或完整聊天框架。

## 音频硬件与资源

Plus的BH1098G提供时钟，ESP32-S31为I2S从机、Philips格式、左右双槽、每槽32位。左/偶数槽是麦克风，右/奇数槽是扬声器回采参考，不是立体声双麦。当前语音配置16kHz，麦克风转PCM16 mono；历史实现沿官方 `bit_shift=true`、`left_align=true`、32位右移12再限幅，不等于最佳有效位或增益已校准。只改WAV头不能提高实际采样率。

引脚和端口见 [设备档案](plus-hardware.md)。需要完整初始化细节时，在已获取的固定官方源码读取 `main/boards/common/audio/bt_audio_codec.cc`、`main/boards/metalio-e-ink4-plus/periph/metalio_audio.cc` 和 `docs/audio-self-test-diagnostics.md`。仅复制必要驱动/适配，不读取整个官方系统做上下文。

P14是共享供电/复位，普通停止录音/播放不能拉低它，否则显示供电失效。复位由协调层排空物理刷新、取得panel/aux门并暂停采样，按板级时序复位；历史流程低3秒、恢复高后等700ms，再UART `AT+RX=2`、等待约700ms、`AT+MODE=1`，确认 `SET MODE 1` 后启I2S。不要持有全局I2C锁睡3秒，不递归获取同一硬件门；错误路径恢复共享轨，无法恢复时明确硬件失效。正常停用关闭PA、释放通道，整机关轨由深休画面完成后统一执行。

录音、写卡、播放与网络在worker；UI只投递命令并读快照。固定块流式处理，不把长录音整体塞RAM。内部DMA可用内存和最大连续块比PSRAM总量更直接：只需录音优先RX单工，勿无需求分配TX。已成功的短片段配置使用12288字节RX DMA环；这是实例，不是任意应用预算。15秒×16k×PCM16 mono为480000字节片段，可用PSRAM，DMA/内部栈另算。收音成功不证明全双工或15秒极限已验收。

等待逻辑核对实际 `CONFIG_FREERTOS_HZ`：100Hz 时 `pdMS_TO_TICKS(1/2/5)` 为0，`vTaskDelay(0)` 不能使高优先级任务阻塞以让低优先级预读任务工作。确需阻塞等待时保证至少1 tick或采用事件/通知；有微秒级时序要求时选择相应驱动/计时机制，不把毫秒参数当实际等待时长。播放器曾因零tick等待发生预填/停止超时，目标构建及主机检查修正通过，真机播放仍需独立验证；不要把这项修正表述为声音连续性已验收。

## 短音效：功放预热、TX 就绪与会话复用

测试006的有声计算器v1.0.0在模式应答和I2S配置完成后便报告ready，尚未启动TX或验证实际传输；每键才开NS4150B功放，立即发送约32ms短音后关断，理想功放开启窗口约60ms。本次修复说明所列器件启动时间为约120ms典型值，不是保证上限；短音可能在启动静音阶段已送完。该说明报告旧生产实现的主机模型复现了早发短音和无时钟假ready，模型不是设备声学测量。

可复用顺序：预填零值PCM → 启动I2S TX → 检查DMA EOF等真实传输进展 → 开启PA并等待足够的稳定时间，期间继续检查TX进展 → 满足条件后宣布会话ready，再播放短音效。启动检查需有界超时，无时钟或无进展时报告失败；仅完成配置、延时结束或PCM入队不能独自证明就绪。v1.0.1采用至少约200ms功放预热，普通键音64ms、等号音96ms、测试音约500ms；这些是本案例参数，按具体硬件和场景选择，不作为所有应用的固定常数。

频繁按键音、游戏提示音优先复用已就绪的TX/PA会话：空闲送静音PCM，播放事件只切换有效数据，避免每个短音重复启停功放。低频或节电场景可关闭，但重新开启须完成相应启动、预热和就绪检查；锁屏、静音、音量0、退出和恢复的会话策略按应用语义确定，保留P14共享供电及尾部DMA排空约束，不强制所有应用永久开PA或锁屏即停声。

区分PCM生成、I2S/DMA入队或排空、TX/PA就绪和扬声器实际可听发声。短音无声时先用足够长的独立测试音检查链路，再查短音启动与过早关断；日志和主机WAV不能代替真机试听。用户后续真机确认v1.0.1经一次修复后按键发声正常；这是本案例的可听输出证据，不扩大为各音量档、锁屏恢复、测试音及所有新应用均已分别验收。

## 录音与回放

用户明确启动的长录音/播放向应用idle协调器成对登记开始/结束；真正完成与资源释放后才解除自动深休暂缓并重新计时。短按锁屏不结束录音；手动长按深休则主动停止、完成文件保存再深休。定时刷新或轮询不登记为用户长任务，不让后台任务永久阻止10分钟默认。产品语义见[产品规范](../../product-conventions/MODULE.md)。

实际采样开始才进入录音计时；按采样数截到业务上限，不用屏幕更新次数估时长。检查RX溢出、无时钟、短写和I/O错误。录音中用独占新建 `.part` 防覆盖，周期补真实WAV长度并同步；停止后补头、同步、close全部成功才发布最终文件。不自动删除残片，不把残片列为成功录音。完整落盘但硬件清理失败要分别报告，不能丢掉真实saved/path。

播放校验RIFF/编码/声道/采样率/位深/数据边界，分块读写，处理I2S部分写入并排空尾部再停PA。DMA入队不是声音已经播完；完成事件以实际排空/回调为准。物理音量键要接入实际增益链，屏幕数字变化不能代替听感；播放音量不改录音增益或已保存PCM。音量映射、余量和静音策略按实际应用，别把实例25/100或每档5当作设备定律。

AI键不要求网络，业务可为点击录停或按住讲话；消抖、上电按住、锁屏/Flash跨界、松手重武装一并处理。锁屏若允许后台录音，继续采样和到时保存但禁输入；深休则先结束并完成保存。控制器在锁屏时不能跳过所有worker快照而漏掉到时保存。

证据：Plus录音机1.0.0-plus.1用户确认录到讲话并可回放，相关版本有保存/返回日志；高保真、音质根因、全时长、坏卡/断电以及每项独立重刷并未因此全部通过。主机peak非零不代表听过声音，峰值触顶也不足以独自证明持续削波。

## 语音转写是可替换业务适配器

采集、PCM所有权、可取消请求、文本插入与服务供应商分开。接口输入是用户授权片段，输出文字或有界错误；选择服务后再核对公开API、鉴权、传输格式和用户配置，不假定官方聊天服务对独立固件免费开放。

未配置后端明确失败，不上传、不伪造文字；保留键盘/保存/退出。后台离线或准备失败用状态提示，用户实际发起请求后失败最多提示一次，不让“取消→Idle→清错误→再弹窗”循环封死编辑。

每次采集/网络请求带代次与原文档/光标身份；取消、切页、锁屏或上下文变化后拒绝迟到结果。PCM只有一个所有者，网络调用真正返回后才释放；Idle必须晚于采样、网络、PCM和临时对象全部结束。保存返回/Flash切换前等待真正Idle，不只检查按钮消失或busy布尔值。测试迟到成功、准备失败后重试、部分任务创建失败、重复结果与取消释放。

现有经验只有本地短片段采集及主机状态机验证，**没有真实STT端到端成功验收**；不将候选API接线写成现成可用能力。新服务完整成功需真实请求、文本插入、持久化及错误兜底证据。

## 音轨移植与动画

有原稿时读实际音轨/脚本/数据，不从截图猜业务。拆清源PCM、预混、局部增益、BGM、总音量和输出格式；避免预混后再次叠同一和声，或把所有声部RMS拉平改变原意。源素材摘要不变，设备补偿在明确链路。用真实worker和实际素材查内部饱和、最终削顶、样本边界/时长，再由用户试听；单段数字安全不能推广全部组合。

前景请求、BGM资格、硬件会话分别管理。视觉弹窗不必重开PA或重置BGM游标；退出/锁屏/Flash/深休按业务撤销资格并等待Shutdown。取消应覆盖worker取命令、部分写入和替换等分支，迟到旧PCM不能混入新片段。音效与马达/屏幕声分开对照，不把起播点声未经测量说成唯一电气根因。

动画各帧固定画布/缩放/锚点。线稿在最终像素处理；alpha先按正确方式采样、白底合成后再落黑芯，否则黑轮廓会再次被alpha稀释。静态灰图与动态黑白固定网点分开；网点固定空间相位，勿每帧随机重采样。

仅当变化像素的新旧值均为黑白且底层可跳过未变像素时选DU；角色移开恢复真灰背景应走相应灰阶路径。动画按物理完成回执推进，音乐业务时钟独立，不能用挤队列和跳帧虚报帧率。真实游戏验收与独立声画小测试是不同证据；没有光学、声学或全温度测试就保留边界。
