# 许可与知识产权

目标是让关键依赖的义务可执行，同时保持用户创作顺畅。不是每一步向用户索要法律确认；来源不明且影响技术路线的依赖不能用一句免责声明放行。保留版本、来源、许可、署名、修改与生成规则；内部使用、交付Skill源码、分发BIN的义务分别检查。

## 本版处理

- 字体用font-support的Noto衍生Plus Mono Sans，保留OFL/原版权/改名说明；运行时代码许可单独记录。
- 拼音读音/输入核心与词频分开。词频换成固定wordfreq衍生排序，按其数据CC-BY-SA及来源署名处理；不能把Apache代码许可说成数据许可，也不能带回JunDa排序。实际记录见text-input。
- EPDiy驱动保留上游LGPL-3.0与GPL-3.0全文，不能用CloudZao工程根MIT覆盖其第三方驱动。固定来源及裁剪差异见底座provenance和licenses/driver-origin.md。新应用静态链接分发时，准备相应库源码、修改说明与允许重新链接的应用目标文件/必要构建资料；具体范围依实际组合核对。不能自动要求公开整个固件口袋源码，也不能擅自许可用户的私有代码。
- ESP-IDF及参与链接的组件要保留各自许可/NOTICE；基础清单不声称穷尽所有SDK子组件。新增网络库、素材、音频、网页内容或服务条款同样记录。仅提供网址不当然允许重分发其内容。
- 本Skill和项目自研部分不因含开源依赖就整体变为MIT；第三方各自许可只覆盖对应范围。作者/甲方对自研部分的商业分发许可由权利人决定，不在生成器里代授权。

## 生成实际清单

`scripts/emit_licenses.py --project <WORK工程>` 先输出基础真实使用项；使用拼音加`--pinyin`。首轮构建后加`--build <构建目录> --sdk <IDF_PATH>`读取真实组件清单、收集组件许可，再编译更新帮助页。新增依赖通过`--extra <JSON>`明示名称/版本/来源/许可文件；不能把未用组件全塞到“本固件使用”里。

输出包括可达的`main/generated/license_generated.h`、`third-party-licenses/`、`license-inventory.json`和《第三方许可与知识产权说明.md》。帮助页引用同一清单全文并可翻页；设备字库无法显示的字符用`[U+XXXX]`转写，交付许可原文保留原始字节。改依赖后重新生成并链接，检查帮助页未被链接器裁掉。

这些工具辅助归纳，不是法律审查或自动商用放行。详细义务和待确认项放文档；最终回复一句话提示用户看该文档与“帮助→开源许可”。遇到无法确认的关键来源或互不兼容的许可，说明具体组件、使用位置、可替换/取得许可的选项并暂停该依赖分发，不要无声改用户设计。
