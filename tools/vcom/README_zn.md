# VCOM 产测工具

**中文** | [English](README.md)

USB 扫描枪作为电脑键盘输入；网页通过设备原生 USB Serial/JTAG 端口发送校准请求。设备执行蓝牙芯片写入、Flash 保存和回读比对，再将负毫伏值交给显示线程应用。操作结果同时显示在设备顶部提示中。设备回复本地保存成功后，HTML 使用电脑网络自动 POST 上报；服务端确认后显示“VCOM 写入和同步成功”。

## 使用

需要 **蓝牙芯片固件 1.08 及以上**，旧版不支持校准记录的持久保存与读取。

在工程根目录运行以下命令，通过桌面 Chrome 或 Edge 打开 [本地工具](http://localhost:8765)：

```sh
python -m http.server 8765 --bind 127.0.0.1 --directory tools/vcom
```

也可通过已有 HTTPS 静态服务器提供这些文件。此工具无需安装前端依赖。先烧录包含产测服务的固件，并关闭占用串口的监视器；点击“连接设备”，选择设备的原生 USB Serial/JTAG 端口。UART 转接板、蓝牙芯片串口和虚拟 U 盘接口不等同于该端口。

工具连接后自动读取蓝牙芯片校准记录。“端口日志”右侧的“重启设备”通过 DTR/RTS 发送硬复位信号；操作进行中不可使用，无需设备命令支持。工具保留串口以接收启动日志；若 USB 重新枚举导致断开，需重新连接。复位信号发送不代表设备已成功启动，也不能代替蓝牙芯片断电持久性测试。将扫描枪设为标准英文字母数字键盘输入并在末尾发送回车，把焦点放到“扫码内容”；扫码框按原始键位收集字符，避免中文输入法将按键组合成汉字，也支持粘贴 ASCII 文本。屏幕标识与负电压之间可以没有空格，例如 `E0470A14-AF_TEST-1.38`；收到 `E0470A14-AF_TEST -1.38` 这样的完整内容后，工具提取 `-1380mv` 并在校验通过后自动发送。“自动写入并校验”默认开启，可取消，取消后仅填充本次参数，由手动按钮提交。每次新扫码开始会清空旧屏幕标识和电压，避免无效数据沿用上一条参数。此处仅为格式示例，写入必须使用当前屏幕标签的实际值。手动输入屏幕标识和负毫伏值后，也可以点击“写入并校验”。同一时间仅允许一笔操作。网页结果使用非阻塞消息提醒，5 秒后自动消失，无需确认，不抢占扫码焦点。

设备测试菜单不提供 VCOM 校准入口，读取和写入统一由 HTML 工具执行。设置 → 屏幕的“黑色深度”仅显示蓝牙芯片最近确认的值，例如 `黑色深度：-1300mv`，不再提供固定档位。

## 端口日志

“端口日志”按原样显示 USB 串口发送（TX）与接收（RX）文本，包括设备日志、协议应答及分包内容。支持暂停显示和清空，仅在网页内保留最近 128KB，不自动保存或上传。网页看不到未经主控输出的蓝牙芯片内部串口数据。

## 存储与接口

蓝牙芯片数据编号 `470` 由本工程保留，记录格式为 `V1|负毫伏整数|屏幕标识`，例如 `V1|-1380|E0470A14-AF_TEST`。不要让其他软件占用该编号。标识最多 79 个 ASCII 字符，仅允许字母、数字、横线和下划线。

USB 请求与应答使用 `@VCOM ` 前缀和逐行 JSON，行尾为 CRLF。`id` 是 1～2147483647 的整数，工具只接受与当前操作匹配的应答。

```text
@VCOM {"id":1,"cmd":"panel.get"}
@VCOM {"id":2,"cmd":"panel.set","panel_id":"E0470A14-AF_TEST","vcom_mv":-1380}
```

写入依次执行 `AT+WDATA=470,...`、`AT+FLUSHDATA=1`、`AT+RDATA=470`。应答示例：

```json
{"id":2,"ok":true,"code":"OK","stage":"done","vcom_mv":-1380,"applied_mv":-1380,"panel_id":"E0470A14-AF_TEST","local_saved":true,"board_model":"metalio-e-ink4-plus","device_mac":"00:11:22:33:44:55"}
```

`vcom_mv` 为蓝牙芯片最近确认的值；`applied_mv` 为显示线程采用的配置值，不是电压实测值。应用异步发生在当前波形结束之后，两者可能短暂不同。工具与设备使用主控 Wi-Fi STA MAC 标识设备。该接口仅供受控的本地产测连接使用。

失败应答包含 `code` 和 `stage`，区分 `ready`、`write`、`flush`、`readback`、`apply` 阶段；例如 `BH_TIMEOUT`、`BH_FLUSH_REJECTED`、`BH_VERIFY_MISMATCH`。本地阶段失败时不发起云请求。工具超时或写入失败后，可重新扫码或手动写入，也可读取核对；设备写入失败后按原参数最多再重试 3 次，每次间隔 1 秒；断开连接取消待执行重试。云端失败不会触发设备重写。

## 云端接口

云端 URL 在工具的服务器地址栏管理，默认留空。“记住地址”默认勾选，可在当前浏览器保存并恢复地址；取消勾选会删除已保存地址。浏览器存储权限受限时可能无法保存。“查询云端”可查看当前设备的云端 VCOM，结果单独显示，不替换本地校准值，也不写入设备。

设备只执行本地写入、保存和回读校验，回复 `ok=true`、`local_saved=true` 后，HTML 才发起 POST。请求使用 HTTPS、`Content-Type: application/json`，正文为 `board_model`、`device_mac`、`vcom_mv`；不额外发送凭据。浏览器跨域请求要求服务端允许页面来源、GET、POST 和 Content-Type 的 CORS 预检。浏览器无法区分网络错误与 CORS 拒绝，均提示连接失败。

只有 HTTP 200、JSON `code=0`，且 `data` 中板型、MAC（忽略大小写）、VCOM 与上传一致才算成功。请求超时为 15 秒。失败提示区分设备写入失败和“VCOM 已写入，同步失败”；后者可点击“重试同步”，仅重新上传，不重写设备。设备和串口协议不再负责云同步。

## 限制


- 仅写入屏幕标签指定的校准值。网页和设备均限制绝对值为 1.0～3.0V（-3000～-1000mv，含边界），步进为 10mv；超出时提示“值异常”，不写入或应用该值。不提供自动校准。
- 开机读取不到有效蓝牙芯片记录时保留板级默认驱动值，界面显示“未知”。运行中失败保留最近确认的驱动配置，黑色深度显示“未知”，不将默认值或历史值伪装成本次读取结果。旧黑色深度档位不再加载。
- 蓝牙芯片写入与 Flash 应答后会回读比对；真正的断电持久性需断电重启并重新读取验证。蓝牙芯片协议未定义事务序号、错误格式全集或 Flash 原子性；超时可能意味着结果不确定，不能解释为一定未保存。
- 驱动采用值只表示显示软件配置，TPS 实际写寄存器与输出电压仍需硬件验证。USB 被其他功能切换、拔线或占用时，需恢复原生串口后重新连接。
- 本地保存成功、云端失败时保留驱动校准值。点击“重试同步”只重新上传，不写蓝牙芯片 Flash。同步状态仅保存在 RAM，不提供跨重启待同步队列或自动补传；重启后先读取本地记录，再手动同步。
