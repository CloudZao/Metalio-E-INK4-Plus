# UI 调度与阅读任务 / UI scheduling and reader work

## 中文

触摸采样只记录输入、投递盖板按键边沿并触发早震。短按、长按和抬起在 UI 任务中按序分发；页面切换会作废旧页面的积压输入。普通页面短按 HOME 按返回栈逐级返回，返回栈为空时进入应用首页；长按 HOME 默认直达应用首页并清空返回栈。页面专用按键处理先于默认行为，网络密码页、连接状态层和传输预览优先关闭当前层级。边沿队列溢出时取消未完成的按压，防止长按连翻持续运行。

百问 AI 分页保留正文内部空行，忽略文本块末尾空白；仅含留白、分隔线或卡片结构的页面不计为回复页。完整分页、流式追加和历史重放共用此规则。

UI 回调负责界面状态、任务提交和结果发布。耗时处理应复用 `Application::Schedule` 的既有任务域，或复用阅读器已有工作任务；回调中不等待任务完成，不同步读写 SD、重建章节或生成正文位图。工作结果应持有自己的数据，使用会话代次校验迟到结果。UI 队列接收成功后由回调释放上下文；投递失败时由提交方释放或保留重试。

横屏及竖屏横排按段处理，逐行按需收紧字距，使行尾文字后的标点优先留在本行。仅在尾标点超出正文宽度时压缩，每个字间距最多收紧约字框高度的 1/12（至少 1px），不缩放字形，并受相邻字形包围框的空白限制，保留至少 1px 净空及标题加粗余量；无法取得字形边界时不压缩。连续标点超出压缩上限时按容量换行，允许标点出现在下一行。原文显式换行保持不变；段首缩进保持原宽。TXT 预览、完整索引及 EPUB／ebook 分页使用相同判断，正文位图与标签回退按同一规则绘制。横排非段末行在正文左右边界间两端对齐，竖排非段末列在正文上下边界间两端对齐；剩余像素均匀分配到字间，不缩放字形。段首保留两字缩进，段末及显式换行自然收尾，跨页续行或续列仍两端对齐；章名保持居中。仅含段末短行的横排页按最终行宽统一居中。竖排保留标点禁则回退，中英文逗号、句号及顿号均占半个字格；普通空格、不换行空格和制表符按字体步进占位，全角空格仍占完整字格。分页与绘制使用相同占位规则。

阅读根容器由正文区和固定高度的信息栏区组成，两区上下紧接，信息标签在底栏内居中；底栏高度为界面字体行高加上下各 2 个纵向缩放像素，不随正文字号改变。四边阅读页边距只约束正文可绘制区域。章节标题保留按内容宽度计算的折行，各行加粗居中；章节序号拆行和标题续行均计入分页高度。行距四档采用字体行高的 0%、10%、25%、40% 作为首选留白比例；行框统一预留装饰空间，横排容纳 2px 净空与 2px 线宽，竖排容纳 2px 净空、1px 线宽及标题向右加粗的 1px 余量，再按可绘制长度计算行数并均分剩余像素到各行上下。装饰开关不改变行框。横排下划线位于本行字形底沿下方，保留至少 2px 净空，线宽为 2px；竖排装饰线位于字格右侧，保留至少 2px 净空，标题加粗时同步右移 1px，线宽为 1px。分页、正文位图及标签回退使用同一行布局，短页保留相同的单行几何。阅读设置中的段距独立于行距，小、标准、大、很大四档分别为 32、56、80、104px，默认标准（56px），自动保存到 NVS。段距与章后距单独计入，页首不追加段前空白；竖排沿列方向分配。修改段距会重新分页，整页图片书籍仅保存偏好。设置页按可见选项调整横线上方区域，底部四项导航的高度和位置固定。正文、信息栏、设置卡片和顶栏的遮挡顺序在建屏时确定，更新尺寸不改变层级；开关设置保留正文抗锯齿状态，未修改排版时复用原页面。开启抗锯齿时退出阅读页，目标页面使用一次 GC16 全刷，不执行推白过渡。

阅读翻页、目录跳转、阅读进度和书签定位统一使用 `RequestReaderNavigation`。`book_nav` 持有请求状态并统一调度前台导航、后台扫描和回收；正文工作模块只接收任务、准备页面并交回结果，不反向调用导航模块。UI 创建独立导航游标，后台任务通过独立只读句柄读取索引和页面，完成目标章节分页、字体预热及正文位图后，UI 才发布当前位置与像素。页面直接发布已有 TXT 预览、物化页或章节缓存，不再保留额外的当前页副本；书签请求只复制目标位置。失败或作废结果保留原阅读位置。相对翻页增量有界累加，绝对跳转保留最新目标。等待中的绝对跳转之后发生的翻页按顺序执行。

开机书库预热任务的优先级低于前台阅读和字体任务，SD 访问竞争时优先准备正文。后台编排不禁用书签、自动翻页和章节导航。TXT 预览以原文字节范围保存和定位书签；上下章提交相对目录增量，在前一个结果提交后计算下一目标。TXT 已识别目录按至多 32 项分批发布，UI 每 100ms 非阻塞接收进度，卡片和目录重绘仍由原队列合并，滚动结束补齐尚未显示的目录变化。普通 TXT 导航等待后台在安全点确认暂停，保留同一次扫描的文件位置、折行状态与已写索引；当前页完成准备、发布并空闲后原地继续。换字体、修改布局、待机或离页时才取消 TXT 扫描；字体使用者退出后才验证和切换新字体，失败保留原字体与偏好。推白方向按真实源位置判断，不使用估算总页码，并随正文像素发布。

前台导航异步等待 TXT 暂停确认或章节计页退出，UI 不等待章节互斥锁。准备期间保留当前底栏，导航成功后更新页码。正文请求结束并空闲后恢复后台统计。全书计页在同一排版下保留已完成章节，从尚未完成的章节继续；只有字体、几何或排版参数变化才清空统计，未完成的单章可重新计页。字体或几何改变须等待现有字体使用者退出，再应用新参数；TXT 当前页预览也在后台计算。阅读背景按几何复用，背景像素和正文合成在工作任务中生成。阅读背景与下划线只影响绘制，开关不改变正文边距、视口、行数和分页。方格以约 32px 的目标间距均分固定内容区，四边完整，边格与内格的像素取整误差不超过 1px；内容区尺寸不变时，翻页不改变格数。

排版与计页完成结果保留在固定交接槽，由 UI 轮询接收，不依赖回调队列容量。分页和 TXT 工作索引完成后关闭写句柄，使 FatFS 文件长度对独立读句柄可见。索引克隆使用实际记录数，TXT 工作文件按会话编号隔离。导航游标在后台交付结果前关闭文件句柄，保留已物化页面，避免延迟回收持续占用文件句柄或删除新会话的索引。

进度保存提交独立 POS3 快照，同一本书尚未执行的保存合并为最新快照；重新打开时也会读取尚未落盘的快照。排队写入及资源回收通过 `sd_access::DeferredTransaction` 预留 SD 事务，卸卡须等其完成。退出前提交最终进度，后台析构不再保存旧位置。`SaveProgress()` 返回成功表示快照已接纳；实际写盘失败另有错误日志。

电量由系统监控任务采样，界面读取原子快照。`DisplayLockGuard` 获取失败时调用方立即返回，只有成功持锁的实例执行解锁。UI 回调日志区分排队与执行耗时，正文准备日志区分排队、导航和栅格化耗时；慢调用按五秒限频并累计省略数。墨水屏波形耗时仍由显示层单独记录。

导航、正文准备和进度写入按上述边界移出 UI 执行路径；书签添加与删除仍在设置回调中同步保存。书籍解析、SD 访问和墨水屏波形仍各有完成时间，硬件驱动内单次阻塞访问需要返回后才能取消。

系统设置在“蓝牙”旁提供“翻页器”设置，显示“自动连接翻页器”选项，“启用中”或“已关闭”按钮独占下一行；当前连接采用与设备列表相同的边框样式，左侧显示名称和地址，右侧显示连接状态，已连接时黑底白字。“设备管理”进入独立全屏页面，沿用 Wi-Fi 配置页的分组、描边和选中样式：已保存设备标明已连接、附近可用或不在附近，另一组显示附近未保存设备及可用状态，不显示信号值。点击已保存设备显示居中弹窗：未连接时提供连接和忘记，已连接时提供断开连接和忘记；支持按键学习的已连接设备还提供自定义按键。点击未保存设备直接连接，已有连接会先断开再切换。已保存设备标记为不在附近时，点击连接仅在顶部提示刷新，不发起连接。手动连接失败后保留列表及失败状态，不自动扫描，刷新或再次连接由用户发起。弹窗右侧的连接或附近状态与左侧名称、地址两行整体垂直居中对齐。进入设备管理或点击“刷新”先扫描 5 秒，在内容区无边框居中显示进度。首轮结束后保留设备分组，每轮扫描结束等待 3 秒再启动下一轮 5 秒扫描；后台发现设备后立即更新对应条目，每轮完成时移除本轮未发现的结果，不因信号值变化重复重建列表。首轮及手动刷新扫描期间隐藏“刷新”按钮；后台重扫时按钮保持显示，点击会取消当前扫描并重新开始一轮。进入设备弹窗、连接、断开、忘记设备、待机或退出页面时停止扫描及后续重扫；可点击“刷新”重新开始。连接时保留设备列表，目标设备右侧显示“连接中”，连接中不重复发起扫描。固定区域不滚动，各组条目仅在内容超出时滚动；固定区域和空、短列表支持下滑唤出全局菜单，存在纵向滚动范围的列表优先滚动。HOME 单击逐级返回，长按回首页；点击弹窗外区域收起弹窗。返回设置保留翻页器选项，离页不主动断开连接。

自动连接开关持久保存。开启时在开机或退出待机后启动 30 秒寻找窗口，优先连接附近已保存的设备，再选择可识别的未保存设备；同级候选优先信号较强者，连接失败会尝试其他候选。手动连接时开启开关，直接尝试所选设备，不启动自动寻找窗口；连接成功后保持开启。寻找窗口内始终没有可用连接则自动关闭并保存关闭状态；用户关闭开关会取消扫描、连接并断开当前设备。设备管理中的主动断开，以及忘记当前连接设备，也关闭自动连接，避免立即连回。待机只暂停活动，保留开关；唤醒按开关重新寻找。手动扫描不改变开关。已保存设备不设固定数量上限，按实际条目存储；旧版本的设备和按键绑定自动迁移。保存失败时保留原配置。协议栈的配对密钥缓存满时按原生策略更新，设备列表和按键绑定仍保留，重连时可重新配对。扫描按地址去重，最多显示六个结果。

已连接的 Free 2、Free3-R、Smart 1-E、HBTR002-X 和 HBTR003-X 均支持按键自定义，提供上一页、下一页，默认 A 上一页、B 下一页，无需学习即可使用。自定义按键和学习在同一居中弹窗内完成，按内容调整大小，明确显示设备和正在设置的动作，短按目标按键后可保存、重新学习或清除绑定；等待超过 20 秒取消学习。保存由 BLE 任务执行，完成后返回按键页，失败保留原绑定并提示重试。学习过程隔离业务输入，两个功能不能共用同一输入，替换时显示提示，各设备的设置独立保存。Free 2 仅分发短按，不识别长按、不启动连翻，也不提供录音或 BOOT 映射。

S31 通过 `sdkconfig.defaults.esp32s31` 将 SDK 支持的无线协议栈 BSS 和 NimBLE 主机动态数据放入 PSRAM；关闭 Wi-Fi 的 IRAM、RX IRAM 和额外 IRAM 加速，为双无线协议栈和 DMA 留出内部 RAM，Wi-Fi 吞吐量可能降低。

翻页器使用片上 BLE Central，与串口蓝牙音频模块独立。Free 2 连接后发现 `0x1812` 服务，检查其中支持通知的 `0x2A4D` 特征（最多 8 个），读取各特征的 `0x2908` Report Reference，对所有 Input（`1`）报告在对应 `0x2902` 写入 `01 00`，持续记录各报告的原始通知；只有已验证的 Report ID `1`、`3`、`4` 参与 Free 2 按键解码，其他报告仅用于协议识别，不触发翻页或按键学习。需要加密时尝试无输入输出配对。按描述符识别报告，不依赖固定特征句柄；不同翻页器可使用不同报告编号。同一连接以首个收到有效非零按键的报告作为输入通道，避免其他报告的空值干扰按键去重。

Free 2 的 Report ID `1` 使用单字节方向指令：`01` 默认上一页，`02` 默认下一页，每条通知触发一次短按，不依赖松开通知；连续相同指令均可触发，也可用于现有上下翻页按键学习。Report ID `3`、`4` 使用三字节通知：`01 00 00` 为按键 A，`02 00 00` 为按键 B，`00 00 00` 清除当前协议按键状态。同一按压内重复的非零状态只分发一次；全零后再次收到非零状态视为新的短按。其他长度、组合位或保留字节非零的报告均忽略，不改变按键状态。

按键事件经独立有界队列进入 UI，由 `pager_key_handler` 调用盖板键已有的 `VkKey_Dispatch`。所有页面沿用底部上一页、下一页按键的现有短按行为，包括返回和翻页；没有对应行为的页面保持原逻辑。BLE 模块不调用具体应用页面。跨页面积压事件失效，进入学习、断开和待机会作废待处理输入，队列溢出时清空积压。手动浅睡前停止并释放 BLE，连接不跨浅睡保持，不支持翻页器唤醒阅读器；退出待机后是否自动重连由开关决定。

Free3-R 订阅 HID Input 报告并保留原始日志，仅解码 Report ID `3`。三字节通知 `02 00 00` 默认上一页，`01 00 00` 默认下一页，`08 00 00` 固定进入待机；`00 00 00` 清除按键状态，同一次按压中的重复报告不重复触发。`00 02 00` 及其他未识别数据仅记录，不映射动作，也不改变去重状态。待机键不参与翻页按键学习，通过现有电源键短按入口进入待机，沿用 OTA、USB 占用及传输收尾逻辑；已进入待机时忽略翻页器输入。

Smart 1-E 按广播名称识别，支持扫描、连接、已保存设备管理和自动重连。Report ID `1` 使用单字节指令：`01` 默认上一页，`02` 默认下一页，`06` 固定进入待机；每条通知触发一次短按，不依赖松开报告，其他数据仅记录。翻页键支持自定义学习，待机键不参与学习。所有 HID Input 通知保留原始日志。

HBTR002-X 和 HBTR003-X 共用轨迹协议。Report ID `2` 使用四字节轨迹报告：首字节 `07` 表示接触，`02` 或 `00` 结束接触；后三字节打包 12 位横纵坐标。横坐标增加默认上一页，减少默认下一页，完整横向轨迹仅产生一次短按；小幅抖动、纵向轨迹和不完整数据不触发翻页。Report ID `1` 的 `00 10` 固定进入待机，`00 00` 为松开。翻页键支持自定义学习，待机键固定；断开、切换设备或取消输入时清理未完成轨迹。

蓝牙 DEBUG 日志记录收到的每条原始通知，包括连接句柄、特征句柄、Report ID、长度和全部十六进制数据；较长报告分块打印，不设条数上限。扫描轮次和原始通知使用 DEBUG；常规日志保留新设备发现、连接、报告编号和类型、通知订阅句柄、断开原因、已分发动作及绑定保存结果，便于比对原始通知与分发动作。

## English

Touch sampling records input, queues cover-key edges and triggers early haptic feedback. The UI task dispatches click, long-press and release events in order. On ordinary screens, a short HOME press returns one level through the navigation stack and reaches the app launcher when the stack is empty. By default, holding HOME opens the app launcher and clears the stack. Screen-specific handlers run first: network password pages, connection status overlays and transfer previews close their current layer before leaving the screen. Screen changes invalidate queued input from previous screens. Queue overflow cancels incomplete presses to stop page-repeat actions safely.

Baiwen AI pagination preserves internal blank lines and ignores trailing whitespace in text blocks. Pages containing only spacing, dividers, or card structure do not count as reply pages. Full pagination, streaming appends, and history replay share this rule.

UI callbacks update state, submit work and publish results. Reuse the existing `Application::Schedule` task domains or reader workers for expensive operations. Callbacks must not wait for workers, access SD synchronously, rebuild chapters or generate page pixels. Results own their data and carry a session generation. Accepted UI messages transfer context ownership to the callback; rejected messages remain the submitter's responsibility.

Landscape and portrait horizontal text is processed by paragraph, with each line tightened only when needed to keep trailing punctuation with the preceding text. Each character gap may shrink by up to approximately 1/12 of the font line height (at least 1px), without scaling glyphs. Compression is also bounded by the blank space between glyph boxes, preserving at least one clear pixel plus room for bold headings. Glyphs with unknown bounds disable compression. Punctuation that exceeds this limit wraps at capacity and may start the next line. Explicit source line breaks and paragraph indent widths are preserved. TXT previews, full indexes, and EPUB/ebook pagination share this decision; raster output and label fallback apply the same spacing. Non-final horizontal lines justify between the left and right content boundaries; non-final vertical columns justify between the top and bottom boundaries. Remaining pixels are distributed evenly between glyphs without scaling them. First lines retain a two-character indent. Paragraph endings and explicit line breaks remain naturally spaced, while continuations across pages remain justified. Chapter headings stay centered. The reading root contains an upper reading area and a fixed-height information footer. They meet without a gap, and the footer label is centered. The four spacing presets prefer 0%, 10%, 25%, or 40% of the font line height as blank space. Layout determines complete rows and distributes remaining pixels above and below them. Decoration switches never change the row geometry. Horizontal underlines leave at least two clear pixels below the row's glyph bounds and are two pixels thick. Vertical rules sit to the right of the glyph cell with at least two clear pixels and a one-pixel line width; bold headings move the rule one pixel farther right. Pagination, raster output, and label fallback share this layout; short pages retain the same row geometry. Visible settings resize the area above the divider while the four bottom navigation items keep their height and position. Screen creation fixes the stacking order of body, footer, settings and top bar; resizing preserves that order. Opening and closing settings preserves body antialiasing and reuses the page when layout has not changed. Page turns, table-of-contents jumps, progress seeking and bookmark navigation share `RequestReaderNavigation`. Relative turns accumulate within a fixed limit; absolute requests retain the latest target. Turns queued after a pending absolute request execute afterward.

Boot library warmup runs at a lower task priority than foreground reading and font work, giving page preparation precedence when SD access is contended. Background layout does not disable bookmarks, automatic page turns or chapter navigation. TXT previews save and restore bookmarks by source byte range. Chapter buttons submit relative table-of-contents increments, resolved after the preceding navigation commits. Recognized TXT headings are published in batches of at most 32 entries. The UI receives progress without blocking every 100ms; existing queues coalesce card and contents rendering, and scrolling completion applies unseen contents changes. Ordinary TXT navigation waits for a pause acknowledgement at a safe point, preserving the same scan, file position, line-breaking state and written indexes. Scanning continues in place after page preparation, publication and an idle interval. Font or layout changes, standby and leaving the reader cancel TXT scanning. Font replacement waits for existing font users, validates the new font and preserves the old font and preference on failure. Wipe direction follows actual source positions rather than estimated page numbers and is published with page pixels.

Foreground navigation asynchronously waits for a TXT pause acknowledgement or for chapter counting to stop. The UI never waits for the chapter mutex. The footer retains its current content during preparation and updates after successful navigation. Background scans resume after foreground work becomes idle, keeping completed chapter counts for the same layout and continuing with unfinished chapters. Only font, geometry or layout changes invalidate those counts; an interrupted chapter may restart. Font and geometry changes wait for existing font users before applying new parameters. Fixed completion slots retain layout and counting results until the UI polls them, independent of callback queue capacity. Progress saves submit independent POS3 snapshots. Pending saves for the same book merge into the latest snapshot, which reopening also consults before disk data. Queued writes and resource cleanup reserve SD access through `sd_access::DeferredTransaction`, so unmounting waits for completion. The system monitor samples the battery; UI code reads an atomic snapshot. Callers return when `DisplayLockGuard` fails, and only an acquired guard unlocks. Rate-limited diagnostics separate UI queue and callback time, and reader queue, navigation and rasterization time. Suppressed slow calls are counted. Display-layer logs measure the e-paper waveform separately.

These boundaries move navigation, page preparation and progress writes outside the UI execution path. Bookmark additions and deletions still save synchronously from settings callbacks. Parsing, SD operations and e-paper waveforms take time; cancellation must wait for an individual blocking driver operation to return.

The S31 configuration in `sdkconfig.defaults.esp32s31` places SDK-supported wireless stack BSS and NimBLE host allocations in PSRAM. Wi-Fi IRAM, RX IRAM and extra IRAM acceleration are disabled to leave internal RAM for both radio stacks and DMA; Wi-Fi throughput may be lower.

The page turner uses the on-chip BLE Central independently of the UART Bluetooth audio module. For Free 2, it discovers service `0x1812`, checks up to eight notification-capable `0x2A4D` characteristics and reads their `0x2908` Report Reference descriptors. All Input reports (type `1`) are subscribed by writing `01 00` to their `0x2902` descriptors, and raw notifications from every report are logged. Only validated Report IDs `1`, `3` and `4` are decoded as Free 2 buttons; other reports support protocol identification without triggering page turns or button learning. No-input/no-output pairing is attempted when encryption is required. Reports are identified by descriptors rather than fixed handles, allowing different page turners to use different report IDs. Each connection selects the first report carrying a valid nonzero button as its input channel, so zero values from other reports do not interfere with key deduplication.

Free 2 Report ID `1` uses single-byte direction commands: `01` defaults to previous page and `02` to next page. Each notification triggers one click without waiting for a release report, including consecutive identical commands. These inputs also support the existing previous/next button learning. Report IDs `3` and `4` use three-byte notifications: `01 00 00` is button A, `02 00 00` is button B, and `00 00 00` clears the protocol key state. Repeated nonzero state within one press dispatches only once; a new nonzero state after a zero report is a new click. Other lengths, combined button bits and nonzero reserved bytes are ignored without changing key state.

A separate bounded queue delivers input to the UI. `pager_key_handler` calls the existing bezel click handler, `VkKey_Dispatch`. Every page retains its existing previous/next click behavior, including back navigation and page turns; pages without a matching action retain their existing behavior. BLE does not call individual application pages. Page changes invalidate queued input. Learning, disconnect and standby invalidate pending input; queue overflow clears pending events. BLE stops and releases its stack before manual light sleep, so connections do not survive light sleep. The page turner cannot wake the reader; automatic reconnection after standby follows the switch.

Free3-R subscribes to HID Input reports and retains raw logs, decoding only Report ID `3`. Three-byte notifications default to previous page for `02 00 00`, next page for `01 00 00`, and standby for `08 00 00`. An all-zero report clears the button state; repeated reports within one press do not retrigger actions. `00 02 00` and other unrecognized reports are logged without dispatching actions or changing deduplication state. The standby key is excluded from page button learning. Standby uses the existing power-key click handler, retaining OTA and USB ownership checks and transfer cleanup. Page turner input is ignored while already in standby.

Smart 1-E is identified by its advertised name and supports discovery, connection, saved device management and automatic reconnection. Report ID `1` uses single-byte commands: `01` defaults to previous page, `02` to next page, and `06` enters standby. Each notification triggers one click without waiting for a release report; other data is logged without dispatch. Page buttons support learning; the standby key is fixed. Raw notifications from all HID Input reports remain logged.

HBTR002-X and HBTR003-X share the gesture protocol. Report ID `2` carries four-byte gesture reports: the first byte `07` indicates contact, and `02` or `00` ends contact; the remaining bytes pack 12-bit horizontal and vertical coordinates. Increasing horizontal coordinates default to previous page and decreasing coordinates to next page. One completed horizontal gesture produces one click; small movements, vertical gestures and incomplete data do not turn pages. Report ID `1` uses `00 10` for standby and `00 00` for release. Page buttons support learning; the standby key is fixed. Disconnect, device switching and input cancellation clear incomplete gestures.

BLE DEBUG logs retain every received raw notification, including connection handle, characteristic handle, Report ID, length and all hexadecimal bytes. Longer reports are logged in chunks without a report-count limit. Scan rounds and raw notifications use DEBUG. Normal logs retain device discovery, connection, report IDs and types, notification subscription handles, disconnect reason, dispatched actions and mapping saves to correlate raw reports with dispatched actions.
