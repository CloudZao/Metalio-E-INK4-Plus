# UI scheduling and reader work

[简体中文](ui-scheduling_zn.md)

## Input, navigation and common widgets

Native and paged scrollbars appear on page entry, scrolling or page changes, then hide after three seconds without interaction. Settings, key help and the reading font/contents lists share this rule.

Touch sampling records input, queues cover-key edges and triggers early haptic feedback, retaining the press origin and latest coordinates. Paged gestures and haptic bindings use separate USER_2 and USER_1 object flags so ordinary controls and reading content are not mistaken for paged lists. Pull-down gestures are checked while pressed and on release. Downward swipes in reading areas open the frontlight panel without triggering tap actions, including swipes missed during a refresh. The UI task dispatches click, long-press and release events in order. In immersive reading, default volume-up and volume-down bindings turn to the previous and next page, with hold-to-repeat support. Table-of-contents and settings overlays retain volume control, and custom bindings take priority. Each short or long press can combine global and page functions. Supported pages handle the page function first; other pages use the global function. A dedicated `VkKeyScreenDesc` callback handles standalone page turns and combinations with a global fallback, consuming input at page boundaries without triggering that fallback. Back + Previous retains page-first navigation with a return fallback; navigation keeps its own return and overlay-dismissal behavior. An unassigned long press inherits only page turning from the short press. Pages register the default volume-key policy through `VkKeyScreenDesc`. Hold-to-repeat timers queue at most one pending UI poll; page callbacks run in the UI task, and a released hold is checked again before execution. On ordinary screens, a short HOME press returns one level through the navigation stack and reaches the app launcher when the stack is empty. By default, holding HOME opens the app launcher and clears the stack. Screen-specific handlers run first: network password pages, connection status overlays and transfer previews close their current layer before leaving the screen. Screen changes invalidate queued input from previous screens. Queue overflow cancels incomplete presses to stop page-repeat actions safely.

Baiwen AI pagination preserves internal blank lines and ignores trailing whitespace in text blocks. Pages containing only spacing, dividers, or card structure do not count as reply pages. Full pagination, streaming appends, and history replay share this rule.

Settings pages share functional sections with consistent spacing between sections and tighter spacing between each title, its controls and its description. Home styles, refresh modes, system fonts, system languages, Bluetooth modes, frontlight modes, haptic strengths and power options use rows inside shared outlined groups, with a circle containing a solid dot on the right of the selected option. Selected labels use bold text at the same font size. Saved system-font preferences are read before display construction, and the existing UI poll restores the selected font asynchronously once SD access is available, without waiting for network startup or version checks. Successful manual application and startup restoration show a three-second top notification: “System font applied successfully”. Fonts open a preview before applying; the other selectable options change on the same page. Light sleep shows the duration configured in the board `config.h`; its description reads the same setting. Frontlight brightness buttons are circular and slightly larger than the slider knob; test-page adjustment buttons retain their original sizes. Information rows have explicit heights that grow with wrapped text. Flex centers their contents within the full row, with a font-metric adjustment for the visible glyphs. The page turner shows the current connection label and device name on opposite sides of one row. Settings touch gestures and page keys move by the viewport; leaving a feature page preserves the parent container gesture policy.

## Background work and result ownership

UI callbacks update state, submit work and publish results. Reuse the existing `TaskExecutor::Schedule` task domains or reader workers for expensive operations. Callbacks must not wait for workers, access SD synchronously, rebuild chapters or generate page pixels. Results own their data and carry a session generation. Accepted UI messages transfer context ownership to the callback; rejected messages remain the submitter's responsibility.

The system monitor samples the battery; UI code reads an atomic snapshot. Callers return when `DisplayLockGuard` fails, and only an acquired guard unlocks. Rate-limited diagnostics separate UI queue and callback time, and reader queue, navigation and rasterization time. Suppressed slow calls are counted. Display-layer logs measure the e-paper waveform separately.

## Reader rendering and layout

The default reading card shows duration and progress, with a bookmark toggle at the top right. Fonts and reading settings restore defaults separately. Nine cards open orientation, footer, touch zones, background, writing, antialiasing, spacing, underline and page-turn settings. Individual pages are one level deep; touch actions add a picker with five actions per column. Information fields are selectable. All at bottom keeps them centered in the footer. Top and bottom places the chapter at the upper left, percentage at the upper right, time and battery at the lower left, and page numbers at the lower right. The layout is saved with the reading preferences. The Building status and page-turn toast are hidden. Contents and bookmark lists retain their existing layouts. Controls are black and white without numeric-row separators. The main container owns the shared reader-card frame: 4px side insets, 2px top, side and navigation borders, with no bottom border. Touch-zone panels reuse that frame. Auto-turn and antialias switches initialize from their actual state, keeping the row white with black text; the right-hand toggle uses a black knob on white when off and a white knob on black when on. Clicking toggles the current state. The reading card keeps the existing UI font. Headers are left-aligned and bold. Bordered option text is centered, and the active choice is bold. Captions share a left column. Touch-zone overlays leave the bottom navigation visible, and their reset chip matches the reading-settings size, pill border and right inset. The card height follows the open page and scrolls when the content exceeds the screen. Values and units are laid out separately. EF size controls and adjustments at their bounds use black text on white with dashed outlines.

Paragraph spacing is 0–104px in 2px steps, letter spacing −2–12px in 1px steps, line spacing 0–48px in 1px steps, and each reading margin 0–64px in 2px steps. Select Top, Bottom, Left or Right, then use the shared adjustment controls. First-line indentation is 0, 1, 2 or 3 characters. Unset edges inherit the saved uniform value or legacy preset. Adjusting one edge leaves the other three unchanged; restoring reading defaults resets all four. Line spacing is preferred extra space, subject to the minimum decoration frame and viewport distribution. Underlines offer None, Solid and Dashed; line position uses the same −12–12px numeric row as spacing, in 2px steps. Antialiasing offers Low, Medium and High coverage strength. Automatic page turning uses a 5–45-second interval in 1-second steps; enabling it is session-local.

Holding adjustment buttons updates displayed values; release or cancellation commits once. Pagination, navigation cursors, rasterization and label fallback share text parameters. Letter spacing, line spacing, indentation and alignment contribute to cache fingerprints. Switching alignment repaginates from the current source anchor. A single asynchronous writer serializes reading preferences and coalesces pending snapshots by preference kind. Touch zones use a separate serial writer that coalesces pending configurations and commits NVS before task exit. The latest font request takes precedence; selecting the original font while another font loads supersedes the pending request. Font and contents lists use vertical swipes to switch complete pages without a scrolling animation. Font pages contain up to nine entries; contents pages show nine rows, leaving blank space on the last page. Multi-page lists retain a scrollbar indicating the current position. Font-list borders remain fixed while inner content is clipped. Multi-page lists own vertical gestures; empty and single-page lists retain the pull-down menu gesture. The status-bar rule follows its parent width in both orientations.

Text-only and mixed text/image pages share background L8 text rasterization and glyph decoding, including character spacing, indentation, bold headings, underlines and antialiasing. Mixed pages reserve image slots in pagination order. Images retain asynchronous loading and use positions produced by the worker. Label drawing is used only when rasterization fails.

Landscape and portrait horizontal text is processed by paragraph, with each line tightened only when needed to keep trailing punctuation with the preceding text. Punctuation normally retains its original font advance, glyph position and baseline. Only when trailing punctuation exceeds the line width is the required amount of trailing blank space reclaimed from a final comma, period or enumeration comma, leaving a two-pixel right margin. Any remaining reduction is distributed in proportion to the available blank space at each gap, without further tightening. Tight gaps remain unchanged rather than limiting the entire line. Each gap may shrink by up to approximately 1/12 of the font line height (at least 1px), preserving at least one clear pixel plus room for bold headings. Glyphs with unknown bounds disable compression. When compression exceeds this limit, horizontal and vertical writing both roll back to the latest legal break, keeping closing punctuation off line starts and opening brackets or quotes off line ends. Capacity-based splitting applies only when an inseparable group exceeds a complete row or column. Horizontal English text is measured by word. After reserving the hyphen width, a word may be split with a display-only hyphen when at most two letters remain; otherwise the whole word moves to the next line. Words longer than a complete line are split to fit, and internal apostrophes stay with the word. TXT, EPUB and ebook share this decision; added hyphens do not affect source positions or bookmark excerpts. Explicit source line breaks and paragraph indent widths are preserved. TXT previews, chapter pagination, and EPUB/ebook pagination share this decision; raster output and label fallback apply the same spacing. Reading settings provide an Alignment row directly above Text layout, with Left and Justified choices. Justified is the default. The preference is saved and included when restoring reading defaults, and applies consistently to TXT, EPUB and ebook. Left alignment uses the full horizontal content column and keeps its left boundary; vertical text starts at the top without stretching gaps. Justified mode aligns non-final horizontal lines between the left and right content boundaries and non-final vertical columns between the top and bottom boundaries. Remaining pixels are distributed evenly between glyphs without scaling them, with no extra horizontal space before closing punctuation. First lines retain the selected indent width. Paragraph endings and explicit line breaks remain naturally spaced; continuations across pages use the selected alignment. Chapter headings stay centered. Horizontal pages containing only short paragraph endings center a shared column using final rendered widths only in Justified mode. Vertical writing retains punctuation-aware break rollback. ASCII and Chinese commas and periods, plus the Chinese enumeration comma, advance by half a cell. Spaces, non-breaking spaces, and tabs use their font advances; ideographic spaces retain a full cell. Pagination and raster output share these advances. TTF pagination retains cached advances, while spacing safety uses the same full glyph bounds as drawing. Font, size, orientation or margin changes trigger repagination.

The reading root reserves fixed-height information rows around the body: one footer in All at bottom, or a header and footer in Top and bottom. Rows without selected fields are hidden and return their space to the body. Information rows use the UI font, independent of the body font size. In Top and bottom, the upper text aligns vertically with the system status text, and the inner gaps to the body are half those of the original layout; the lower text retains its distance from the screen edge. Reading margins constrain only the drawable content area. Chapter headings retain line breaks calculated for the content width, with each line bold and centered. Separate chapter numbers and wrapped title lines both count toward page height. Without a continuous line-gap value, legacy settings retain blank space of 0%, 10%, 25%, or 40% of font height; continuous settings use pixels. Every row reserves decoration space: two clear pixels and a two-pixel horizontal underline, or two clear pixels, a one-pixel vertical rule, and one extra pixel for bold headings. Layout determines complete rows and distributes remaining pixels above and below them. Decoration switches never change the row geometry. Horizontal underlines default to two clear pixels below the row's glyph bounds, adjustable through the line-position offset and are two pixels thick. Vertical rules sit to the right of the glyph cell with at least two clear pixels and a one-pixel line width; bold headings move the rule one pixel farther right. Pagination, raster output, and label fallback share this layout; short pages retain the same row geometry. Paragraph spacing is independent of line spacing, initially retaining the legacy Standard value of 56px and saving continuous adjustments to NVS. Paragraph and post-heading gaps are added separately, with no extra gap before the first paragraph on a page. Vertical writing distributes space between columns. Changing the paragraph gap repaginates text; image-only books save the preference without applying it. The card retains its header and bottom navigation while individual setting pages open one level deeper; touch actions have an additional picker. Screen creation fixes the stacking order of body, footer, settings and top bar; resizing preserves that order. Opening and closing settings preserves body antialiasing and reuses the page when layout has not changed. Leaving a reader with antialiasing enabled uses one GC16 full refresh for the destination page, without a wipe transition.

## Reader navigation and first-page recovery

Page turns, table-of-contents jumps, progress seeking and bookmark navigation share `RequestReaderNavigation`. The `book_nav` controller owns requests and schedules foreground preparation, current-chapter layout and cleanup. The page worker only accepts work, prepares pages and returns results; it never calls back into navigation logic. The UI creates an independent navigation cursor. A worker reads indexes and pages through separate read-only handles, paginates target chapters, prewarms fonts and rasterizes text. The UI then publishes the position and pixels using the existing TXT preview, materialized page or chapter cache, without an additional current-page copy. Bookmark requests copy only the target position. Failed or invalidated results preserve the previous position. Relative turns within a chapter can retain prepared prefetch results. Cross-chapter commits clear the previous prefetch chain and prepare subsequent pages from the active chapter cache, preventing independent pagination files from being mixed. Relative turns received during foreground preparation or pending rendering are consumed without queuing; optional prefetch alone does not block navigation. Absolute requests retain the latest target. Hold-to-repeat does not replay missed intervals.

Boot library warmup runs at a lower task priority than foreground reading and font work, giving page preparation precedence when SD access is contended. Background layout does not disable bookmarks, automatic page turns or chapter navigation. TXT previews save and restore bookmarks by source byte range. Chapter buttons submit relative table-of-contents increments, resolved after the preceding navigation commits. Recognized TXT headings are published in batches of at most 32 entries. The UI receives progress without blocking every 100ms; existing queues coalesce card and contents rendering, and scrolling completion applies unseen contents changes. Font or layout changes, standby and leaving the reader cancel current-chapter preparation. Generations guard publication. Wipe direction follows stable source positions and is published with page pixels.

First-page recovery is independent of the full contents structure. TXT opens one page near the saved byte offset; EPUB/EBOOK parse only the anchored source document and prepare one preview page. Neither a full-book scan nor chapter page totals delay this preview. Compressed documents may still need to be read from their start to the anchor; very long source files and legacy page-number conversion can therefore take longer. Until structure is ready, chapter pages show `--/--` and EPUB/EBOOK percentages show `--%`. TXT uses source-byte progress. Chapter names stay hidden when their contents target is not yet known.

After first paint, the existing low-priority layout worker reads the font-independent `.rsi` structure cache. On a miss it scans directory anchors and content lengths, then paginates the active chapter and reconnects the page using its latest source anchor. Size, modification time, format, parser version, counts, position ranges and checksum validate the cache. Invalid caches are rebuilt. Cache write failures do not invalidate readable content; failed structure or pagination work preserves the preview. Cache updates use temporary files and the existing storage commit mechanism. Book content and resume records are not disposable cache data.

A worker-owned staging session retains scan results; the UI only publishes completed structure and pages. During structure preparation, the first page-turn request is retained and cancels background work. Target-page preparation waits for a safe-point exit rather than a full-book scan or complete chapter pagination. Layout tasks capture their cancellation generation at submission, and cancelled results cannot overwrite the reading position. Repeated input does not accumulate; background layout resumes when navigation is idle. TXT retains decoder buffers, heading state and byte position. EPUB/EBOOK retain completed source files and may rescan the interrupted file. Standby and departure cancel work before closing handles; waking resumes unfinished work. Page turns, bookmarks and native contents navigation remain available before full structure is ready, with bounded backward history. Arbitrary EPUB/EBOOK percentage seeks wait for full structure and preserve the current page on failure.

Adjacent effective EPUB directory targets define reading chapters, including subdivisions within one file and continuations across files. Duplicate targets share a range; missing anchors fall back to their content document start. EPUB/EBOOK without native contents paginate by source document or chapter while retaining the empty-contents UI. TXT retains at most 8,000 contents entries; remaining content stays readable in the final chapter. TXT without detected chapters stays in streaming mode without a full-book page total.

Foreground navigation uses an independent cursor to paginate only the target chapter. Successful publication updates text, chapter page numbers and a full-book percentage based on cumulative content positions. Failure or cancellation preserves the current page and position. Delayed chapter transitions show “Loading chapter…”, cleared on completion, failure, a new request, standby or departure. Text prefetch expands by page in the reading direction according to available memory. After the nearest page, the same worker prioritizes pagination of the adjacent chapter in the reading direction, then its entry-page raster and more distant pages. Completed pagination is retained independently of rasterization; a matching partial hit renders the prepared cursor without repeating navigation. Cached pixels publish immediately once source-session navigation is no longer active. The same worker prepares the adjacent chapter in an independent cursor; complete pagination remains on SD, with only page and index windows in RAM. A matching navigation request takes ownership when published. Cancellation and stale results never change the reading position. Background updates to the same settings page wait until a numeric adjustment is released. Font-size changes update the existing controls without rebuilding the font list or resetting the scrollbar visibility timer; directory content, page count or selection mode changes rebuild the list. Font and viewport changes repaginate only the current chapter; full-book page caches are no longer read or written. Font and geometry changes wait for existing font users before applying new parameters. TXT preview layout also runs in a worker. Background layers reuse matching geometry; workers generate background pixels and compose them with text. Backgrounds and underlines affect drawing only; switching them keeps margins, the viewport, row counts and pagination unchanged. Grid mode divides the fixed content area at a target spacing near 32px, with complete edges and at most one pixel of rounding difference between edge and interior cells. Page turns keep the same grid count unless the content area changes.

Fixed slots retain layout results and wake the UI through the common completion channel. Page lifecycle updates serve the active page; deferred cleanup continues after departure independently of ordinary message capacity. Active-chapter pages are stored on SD, with two materialized pages and fixed index windows in memory. Navigation shares immutable contents ranges rather than copying the full contents on every turn. Closing completed write handles makes FatFS lengths visible to independent readers. Cursors close file handles before delivery while retaining materialized pages, so delayed cleanup neither holds SD handles nor deletes newer session files.

Optional image, text and adjacent-chapter preparation share one execution slot and use conservative image/page estimates rather than per-allocation reservations. Public image decoding, text rasterization and font loading suspend new optional work and request cache reclamation when their estimated working space is unavailable. Cache owners release idle resources immediately or at a safe point; current pages, active font faces and decoding buffers retain their owners. Reclaim generations reject late optional results. Internal free RAM must remain above the firmware floor; insufficient total or contiguous space still follows the normal failure or fallback path.

Progress saves submit independent POS4 snapshots. Pending saves for the same book merge into the latest snapshot, which reopening also consults before disk data. Queued writes and resource cleanup reserve SD access through `SdAccessDeferredTransaction`, so unmounting waits for completion. Closing submits the final snapshot before ownership transfer; delayed destruction never saves an obsolete position. Successful `SaveProgress()` means acceptance; disk failures are logged separately. TXT stores source byte offsets and paragraph-start flags; EPUB/EBOOK store original source chapter, block and UTF-8 offset; image books retain source page identity. Snapshots include size, modification time, format, parser version and integrity checks; validation failure preserves the original record. POS1/2/3 remain readable with their original time-field semantics. Legacy chapter page numbers are converted to anchors using the old physical chapter boundary during restoration. Legacy TXT first uses a byte anchor, then a matching old `.idx`; otherwise percentage-based paragraph positioning is approximate. Legacy records without file identity or layout metadata cannot establish that the source is unchanged. BKM1 bookmarks retain source ranges; old display page numbers do not determine navigation. Older firmware does not recognize POS4; back up resume records before downgrading. Replaced files, incompatible parser versions or corrupt POS4 records block resume until the user handles the original record.

These boundaries move navigation, page preparation and storage writes outside the UI execution path. Bookmark changes submit independent snapshots to `Storage`; UI adopts them after successful saves. Writes finish after navigation, and failures preserve the previous snapshot. Parsing, SD operations and e-paper waveforms take time; cancellation must wait for an individual blocking driver operation to return.

## Image delivery and cancellation

Detail covers use one worker and retain only the latest pending request. Leaving or submitting again cancels the active decode; the worker waits for the UI to reclaim each result before processing another cover. Calls without cancellation support, such as file opening, check cancellation after returning and retain live resources until then. Inline-image requests transfer ownership only after task acceptance; allocation or creation failure marks the corresponding slots with the existing load-failure message. A2UI images capture the page generation at submission, and atomic generation checks discard stale work and deliveries.
