# 电池检测与电量显示策略

本文描述板型 **metalio-e-ink4-plus**（与 397 同芯片）上 **电量计显示** 与 **充电芯片控制** 的分工与策略。二者独立：电量计只观测与显示；是否真充、何时停充由充电 IC 硬件 + 驱动策略决定。

| 模块 | 芯片 | 代码 | 职责 |
|------|------|------|------|
| 电量计 | TI BQ27220 | `main/boards/common/power/bq27220_gauge.{h,cc}` | 电压/电流采样、SOC 显示、UI 充电标志 |
| 充电 IC | CX25601N | `main/boards/common/power/cx25601n.{h,cc}` | VREG/ICHG/ITERM、EN_CHG/EN_TERM、再充 kick、欠压 BATFET |
| 板级接入 | — | `metalio_power.cc` | I2C1 + 总线锁上挂两芯片；默认 ICHG 1000mA |
| 状态栏 | — | `Board::GetBatteryLevel()` | 电量图标 / 闪电图标（UI 就绪后接） |

---

## 1. 角色分工（物理 vs 软件）

```text
USB 5V ──► CX25601N ──► 电池（BAT）
              │              │
              │              └── BQ27220 测电压/电流（电量计）
              └── 软件写寄存器：VREG / ICHG / EN_CHG / EN_TERM …
```

| 问题 | 谁决定 |
|------|--------|
| 电池支路有没有充电电流 | **物理**（充电 IC + 通路）；电量计只读 mA |
| 何时停充（充满终止） | **充电 IC 硬件**（CV + ITERM 等）；软件可改阈值 / 关 EN_TERM |
| UI 显示几%、是否闪电图标 | **软件**（`GetBatteryLevel()`） |
| USB 表总电流 vs 表计电流 | 不是一路：USB 表含整机耗电；BQ27220 只看电池支路 |

**结论：** 不能靠改电量计参数「设成在充 / 设成满」。改充电行为要动 CX25601N 寄存器与再充逻辑。

---

## 2. 电压关键阈值

| 名称 | 值 | 用途 |
|------|-----|------|
| 充电截止 VREG | **4400 mV** | CX25601N 恒压目标，硬件停充参考 |
| 显示满电 | **4330 mV** | SOC 线性映射的 100%（偏静置开路） |
| 空电 | **3300 mV** | SOC 线性映射的 0% |
| 满电确认 | ≥4330 mV 连续 **30 s** | 才允许目标/显示到 100% |
| 满电退出滞回 | **4280 mV** | 已显示 100% 后，电压未跌破此值前保持 100% |
| 电流死区 | ±5 mA** | 判定充电 / 放电 / 空载 |

充电仍可充到 4400；停充回落后静置约 4330 对应显示满格，减轻 IR 虚高导致的「假满」。

## 3. 电量显示策略（BQ27220）

入口：`Bq27220Gauge::GetBatteryLevel(level, charging, discharging)`。

**不用芯片 SOC 寄存器**（未标定易失真），只用电压线性估算。

### 3.1 流水线

```text
瞬时电压 mV
    │
    ▼
线性 SOC：3.30V→0%，4.33V→100%（≥4.33 先算作 100）
    │
    ▼
60 点滑动平均 →「目标电量」target（每帧可更新，可抖）
    │
    ├─ 未满 30s@≥4330：target 封顶 99
    ├─ 已显示 100% 且 mv≥4280：强制 target=100
    │
    ▼
单向步进 →「显示电量」displayed（约 30s ±1%）
    │
    ▼
对外 level；charging = (电流>+5mA) && (level<100)
```

### 3.2 目标电量 vs 显示电量

| | 目标 target | 显示 displayed |
|--|-------------|----------------|
| 更新频率 | 每次 `GetBatteryLevel`（约 1 Hz 量级） | 约 **30 s** 才允许变 **1%** |
| 是否抖动 | 会（电压/滤波） | 不应来回抖 |
| 方向 | 无 | **充电中只升；未充电只降** |

**例子：** 显示 98%，目标曾到 99%，30 s 计时未结束时目标又掉回 98% → 计时到期时目标不高于显示 → **保持 98%，不会升到 99%**。

### 3.3 插拔电与步进计时

充 / 放 / 空载方向变化（典型：插拔 USB）时，**重开 30 s 步进计时**。

避免：充电阶段计时已到期但「只许升」所以不动，一拔电立刻按「只许降」掉 1%，看起来像「拔电马上改电量」。

### 3.4 到 100% / 离开 100%

| 条件 | 行为 |
|------|------|
| 电压连续 ≥4330 mV 满 **30 s**，且目标允许 100 | 显示可到 100% |
| 已显示 100%，且电压 ≥4280 mV | 保持 100%，不因 4328↔4330 掉到 99% |
| 电压跌破 4280 mV 且未在充（或步进允许降） | 可按 30 s 步进下降 |

### 3.5 UI「充电」标志

| 内部 | 对外 `charging` |
|------|-----------------|
| `raw_charging = (电流 > +5 mA)`，用于单向步进方向 | `raw_charging && level < 100` |

**显示 100% 时即使芯片仍在 CV 尾充，也不报充电**（状态栏不显示闪电图标）。

### 3.6 电流读数含义

- 寄存器 `0x0C`，单位 mA，+ 充电 / − 放电。
- 测试页 `+0 mA` 为原始值（显示不做死区抹零）；「空载」判定用 ±5 mA。
- **不等于** USB 口总电流；系统从 VBUS 取电时，表计可为 0 而 USB 表仍有一百多 mA。

## 4. 充电控制策略（CX25601N）

### 4.1 默认硬件参数（`hw_init_defaults`）

| 项 | 典型值 | 说明 |
|----|--------|------|
| VREG | **4400 mV** | 固定截止，不做 IR 自适应抬压 |
| ITERM | **60 mA** | 尾电流低于此可终止（曾用 180 mA 易误停） |
| ICHG | init 500 mA；板级可改为设置里的 500/1000 | 写 ICHG 时同步 IINDPM |
| DPDM | **关闭**自动识别 | 避免被判 SDP 限流 500 mA；`VBUS_STAT` 常为 0（显示「无输入」不可信） |
| EN_CHG | 上电打开 | 允许充电 |
| EN_TERM | REG0x14 **bit2** | 电流终止使能 |

### 4.2 后台任务（`charger_vreg_task`）

- **VREG 固定**为设定目标（默认 4400），不再随电流抬到 4450 等（曾导致 CC↔CV 软件抖）。
- `Vbat < VREG`：关 **EN_TERM**，避免未到截止就被 ITERM 停掉。
- `Vbat ≥ VREG`：开 EN_TERM，允许正常终止。
- 已终止（`CHG_STAT=NOT`）且电流≈0 且电压仍低于 VREG：`kick_recharge`（关 EN_TERM → toggle EN_CHG）强制再开一轮。
- 低于截止时约 **2 s** 巡检；否则约 **10 s**。
- **欠压保护**：无 VBUS 且 VBAT≤3100mV → `REG0x18=0x01` BATFET Shutdown。

### 4.3 充电状态含义（`CHG_STAT`）

| 值 | 文案 | 含义 |
|----|------|------|
| 0 | 未充电/已满 | 未在充或已终止（不一定真满） |
| 1 | 涓流/预充/CC | 含快充恒流 |
| 2 | 恒压降流 | CV |
| 3 | Top-off | 补电 |

硬件终止后，电压回落到仍高于再充阈值时，可能长时间 NOT；故有软件 kick。再充阈值（VRECHG）属芯片硬件回差，与显示用的 4300/4350 不是同一套逻辑。

## 5. 常见现象对照

| 现象 | 解释 |
|------|------|
| USB 表有电流，表计 +0 mA，芯片「未充电/已满」 | 系统吃 VBUS；电池支路未充或已终止 |
| VBUS 显示「无输入」却在充 | DPDM 关闭导致 `VBUS_STAT` 误报；以电流/CHG_STAT 为准 |
| 插电电压冲高、拔电回落 | IR 压降；显示用单向步进 + 4330/30s/4280 滞回抑制抖 |
| 100% 仍有几十 mA、芯片 CV | 尾充正常；UI 已不显示充电图标 |
| 目标 99%、显示 98%，目标又变 98% | 30 s 后显示保持 98，不会升到 99 |
