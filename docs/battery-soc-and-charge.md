# 电池检测与电量显示策略

本文描述板型 **metalio-e-ink4-plus**（与 397 同芯片）上 **电量计显示** 与 **充电芯片控制** 的分工与策略。二者独立：电量计只观测与显示；是否真充、何时停充由充电 IC 硬件 + 驱动策略决定。

| 模块 | 芯片 | 代码 | 职责 |
|------|------|------|------|
| 电量计 | TI BQ27220 | `main/boards/common/power/bq27220_gauge.{h,cc}` | 电压/电流采样、SOC 显示、UI 充电标志 |
| 充电 IC | CX25601N | `main/boards/common/power/cx25601n.{h,cc}` | VREG/ICHG/ITERM、EN_CHG/EN_TERM、再充 kick、欠压 BATFET |
| 板级接入 | — | `metalio_power.cc` | I2C1 + 总线锁上挂两芯片；默认 ICHG 1000mA |
| 状态栏 | — | `Board::GetBatteryLevel()` | 电量图标 / 闪电图标（UI 就绪后接） |

---

## 1. 角色分工（物理 vs 软件）

```text
USB 5V ──► CX25601N ──► 电池（BAT）
              │              │
              │              └── BQ27220 测电压/电流（电量计）
              └── 软件写寄存器：VREG / ICHG / EN_CHG / EN_TERM …
```

| 问题 | 谁决定 |
|------|--------|
| 电池支路有没有充电电流 | **物理**（充电 IC + 通路）；电量计只读 mA |
| 何时停充（充满终止） | **充电 IC 硬件**（CV + ITERM 等）；软件可改阈值 / 关 EN_TERM |
| UI 显示几%、是否闪电图标 | **软件**（`GetBatteryLevel()`） |
| USB 表总电流 vs 表计电流 | 不是一路：USB 表含整机耗电；BQ27220 只看电池支路 |

**结论：** 不能靠改电量计参数「设成在充 / 设成满」。改充电行为要动 CX25601N 寄存器与再充逻辑。

---

## 2. 电压关键阈值

| 名称 | 值 | 用途 |
|------|-----|------|
| 充电截止 VREG | **4400 mV** | CX25601N 恒压目标，硬件停充参考 |
| 显示满电 | **4300 mV** | 充电线性估算的 100%，同时用于满电确认 |
| 空电 | **3300 mV** | 充放电估算的 0% |
| 满电确认 | ≥4300 mV 连续 **30 s** | 才允许目标/显示到 100% |
| 满电退出滞回 | **4280 mV** | 已显示 100% 后，电压未跌破此值前保持 100% |
| 电流死区 | ±5 mA** | 判定充电 / 放电 / 空载 |

充电显示按 3300～4300 mV 线性估算；有效采样电压持续 ≥4300 mV 满 30 s 后确认满电，并按正常步进升至 100%。满电退出阈值为 4280 mV，充电 IC 的恒压目标仍为 4400 mV。

While charging, the voltage estimate maps 3300–4300 mV linearly to 0–100%. Valid samples at or above 4300 mV for 30 s confirm full charge, allowing the display to reach 100% through normal steps. Full-charge retention ends below 4280 mV; the charger IC's constant-voltage target remains 4400 mV.

## 3. 电量显示策略（BQ27220）

入口：`Bq27220Gauge::GetBatteryLevel(level, charging, discharging)`。

系统监控任务约每秒采样并发布原子快照，监控日志仍约每三秒输出。`Board::GetBatteryLevel()` 和界面读取快照，不在 UI 锁内等待 I²C；采样失败或滤波重置时清除快照。

The system monitor samples approximately once per second and publishes an atomic snapshot; monitoring logs retain their approximately three-second interval. `Board::GetBatteryLevel()` and UI code read the snapshot without waiting for I²C while holding the UI lock. Failed samples and filter resets invalidate the snapshot.

**不用芯片 SOC 寄存器**（未标定易失真），按电流方向选择电压估算曲线。开机或退出待机后等待 **3 s**，首次有效调用才读取显示所需的电压、电流并初始化电量；等待期间隐藏电量图标和百分比，并清除旧显示缓存，不用 0% 代替。底层采样仍供充电控制和欠压保护使用。

未充电时采用 424860-2000 测试表的工步 6：约 1000mA 放电至 3.3V，以实际放出容量 1870.7mAh 归一化为 0～100%，每 10% 提取电压点并分段线性插值。权威取点表维护在 `bq27220_gauge.cc`，电池测试页复用同一换算函数。该曲线对应本次测试的带载可用容量，不等同于静置开路曲线；不同负载、温度及电芯差异仍需整机校准。

充电时采用 3.30～4.30V 的线性估算。测试表充电上限为 4.3V，而当前充电控制目标为 4.4V，不能直接据此建立完整充电百分比曲线；恒压尾充阶段仍由满电确认限制 100%。工步 2 的非满电放电和工步 8 的充至 4.0V 数据不参与本次映射。

### 3.1 流水线

```text
开机满 3s 后的瞬时电压、电流
    │
    ▼
未充电：实测放电曲线插值；充电：3.30～4.30V 线性估算
    │
    ▼
60 点滑动平均（同一曲线每秒最多采纳一个样本）→「目标电量」target
    │
    ├─ 未满 30s@≥4300：target 封顶 95
    ├─ 已显示 100% 且 mv≥4280：强制 target=100
    │
    ▼
向下量化至 5% 档位 → 单向步进 →「显示电量」（每 30s ±5%）
    │
    ▼
对外 level；charging = (电流>+5mA) && (level<100)
```

### 3.2 目标电量 vs 显示电量

| | 目标 target | 显示 displayed |
|--|-------------|----------------|
| 更新频率 | 同一曲线每秒最多一个滤波样本，各入口共享 | 每 **30 s** 最多变化 **5%**，始终为 5% 的整数倍 |
| 是否抖动 | 会（电压/滤波） | 不应来回抖 |
| 方向 | 无 | 充电中只升；未充电只降，满电确认完成时允许升至 100% |

首次有效电量向下量化到最近的 5% 档位，例如估算 53% 显示 50%。退出待机时同样先清除电量和滤波状态，等待唤醒负载稳定 3s 后重新采样，允许一次性跨多个档位校准，以反映待机期间充电或耗电；校准后重新开始 30s 步进计时。之后只有目标跨越档位，且步进间隔到期，才沿允许方向变化一档。首次满电确认完成前最高显示 95%。已确认满电的滞回状态跨待机保留，唤醒等待期间仍不显示电量；3s 后以新电压校验，未跌破满电退出阈值时可校准为 100%，跌破则清除满电状态并按曲线重新校准，避免无条件重置导致 100%→95%→100%。

### 3.3 插拔电与步进计时

充 / 放 / 空载方向变化（典型：插拔 USB）时，**重开 30 s 步进计时**。充电与非充电曲线切换时清除旧滤波样本，保留显示电量，避免两条曲线混合。显示计算和待机重置串行执行，避免监控、状态栏和阅读页并发修改共享状态。阅读页启用电量显示时每秒更新一次，以及时清除插拔充电后的旧标志。

避免：充电阶段计时已到期但「只许升」所以不动，一拔电立刻按「只许降」掉 5%，看起来像「拔电马上改电量」。

### 3.4 到 100% / 离开 100%

| 条件 | 行为 |
|------|------|
| 有效采样电压持续 ≥4300 mV 满 **30 s** | 目标设为 100%，即使尾充终止、电流归零，也允许按正常步进升至 100% |
| 已显示 100%，且电压 ≥4280 mV | 保持 100%，不因满电确认阈值附近的电压波动掉到 95% |
| 电压跌破 4280 mV 且未在充（或步进允许降） | 可按 30 s 步进下降 |

电压/电流读取失败、电压超出有效范围，或相邻有效采样间隔超过 2s 时，重新开始满电确认，避免将未观测时段计入连续高电压时间。读取失败期间各电量显示入口清除百分比，不把默认零值显示为真实电量。

### 3.5 UI「充电」标志

| 内部 | 对外 `charging` |
|------|-----------------|
| `raw_charging = (电流 > +5 mA)`，用于单向步进方向 | `raw_charging && level < 100` |

**显示 100% 时即使芯片仍在 CV 尾充，也不报充电**（状态栏不显示闪电图标）。

### 3.6 电流读数含义

- 寄存器 `0x0C`，单位 mA，+ 充电 / − 放电。
- 测试页 `+0 mA` 为原始值（显示不做死区抹零）；「空载」判定用 ±5 mA。
- **不等于** USB 口总电流；系统从 VBUS 取电时，表计可为 0 而 USB 表仍有一百多 mA。

## 4. 充电控制策略（CX25601N）

### 4.1 默认硬件参数（`hw_init_defaults`）

| 项 | 典型值 | 说明 |
|----|--------|------|
| VREG | **4400 mV** | 固定截止，不做 IR 自适应抬压 |
| ITERM | **60 mA** | 尾电流低于此可终止（曾用 180 mA 易误停） |
| ICHG | init 500 mA；板级恢复设置中的 500/1000/1500，默认 1000 | 写 ICHG 时同步 IINDPM |
| DPDM | **关闭**自动识别 | 避免被判 SDP 限流 500 mA；`VBUS_STAT` 常为 0（显示「无输入」不可信） |
| EN_CHG | 上电打开 | 允许充电 |
| EN_TERM | REG0x14 **bit2** | 电流终止使能 |

充电设置提供 0.5A、1A、1.5A 三档，选择后立即应用并保存，重启后恢复。驱动按芯片 80mA 步进向下量化，实际 ICHG 分别为 480、960、1440mA；实际电池电流还受输入电源、负载及充电阶段影响。

### 4.2 后台任务（`charger_vreg_task`）

- **VREG 固定**为设定目标（默认 4400），不再随电流抬到 4450 等（曾导致 CC↔CV 软件抖）。
- `Vbat < VREG`：关 **EN_TERM**，避免未到截止就被 ITERM 停掉。
- `Vbat ≥ VREG`：开 EN_TERM，允许正常终止。
- 已终止（`CHG_STAT=NOT`）且电流≈0 且电压仍低于 VREG：`kick_recharge`（关 EN_TERM → toggle EN_CHG）强制再开一轮。
- 低于截止时约 **2 s** 巡检；否则约 **10 s**。
- **欠压保护**：无 VBUS 且 VBAT≤3100mV → `REG0x18=0x01` BATFET Shutdown。

### 4.3 充电状态含义（`CHG_STAT`）

| 值 | 文案 | 含义 |
|----|------|------|
| 0 | 未充电/已满 | 未在充或已终止（不一定真满） |
| 1 | 涓流/预充/CC | 含快充恒流 |
| 2 | 恒压降流 | CV |
| 3 | Top-off | 补电 |

硬件终止后，电压回落到仍高于再充阈值时，可能长时间 NOT；故有软件 kick。再充阈值（VRECHG）属芯片硬件回差，独立于电量显示的满电确认与退出阈值。

## 5. 常见现象对照

| 现象 | 解释 |
|------|------|
| USB 表有电流，表计 +0 mA，芯片「未充电/已满」 | 系统吃 VBUS；电池支路未充或已终止 |
| VBUS 显示「无输入」却在充 | DPDM 关闭导致 `VBUS_STAT` 误报；以电流/CHG_STAT 为准 |
| 插电电压冲高、拔电回落 | IR 压降；显示用单向步进 + 满电确认与退出滞回抑制抖 |
| 100% 仍有几十 mA、芯片 CV | 尾充正常；UI 已不显示充电图标 |
| 目标未跨越下一个 5% 档位 | 保持当前显示，直到目标跨档且步进计时到期 |
